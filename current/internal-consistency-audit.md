# 内部一致性审查

审查对象：
$ARGUMENTS

多文件体系的行动冲突发生在**使用点**——某个角色在某一步拿着文档去调工具、写产物、过门禁的接缝处。单份文件各自通读往往自洽，合到同一执行链上才暴露死结。本方法按“谁在什么情境消费什么、跨组件怎样交接”切分角度并发收集，再由主代理统一核实代码与实例、归并根因、交付负责人裁定。

完整任务书见[派遣参考](../docs/internal-consistency-audit/references/dispatch-prompts.md)，实战演进见[历史记录](../docs/internal-consistency-audit/history.md)。

## 重点捕捉的六类冲突

1. **提交与交接失配**：提交流程或格式交代模糊；提示词要求的格式与门禁实际校验格式不同；上游或外部实际给到的变量、字段、任务包结构与文档向消费者承诺的样子不同。
2. **前后推翻**：同一文件或同一链路内，前文给出的规则、权限或假设被后文否定。
3. **多规则/多机制死结**：几条单看合理的规则、门禁或恢复机制同时命中同一状态时互相卡死。
4. **引用落空**：写了 `refer to` 某文件或章节，但目标缺失，或跳过去之后根本没有当前动作急需的那条格式、判据或命令。
5. **首现缺解释**：流程上第一次出现并直接影响行动的专有概念、状态或字段，在执行者此刻可见的上下文里找不到可操作的定义。
6. **异词同指与同词异义**：同一概念在提示词、手册、脚本里换用多个名称，或同一名称在上下游指代不同集合与阶段，导致交接错位。

## 1. 主代理定标（做完两步即停，随后立即扇出）

派发前主代理亲自完成两件事，既避免盲派后无力甄别，也避免自己通读全仓退化成单人硬啃：

1. **枚举全量关系面**：用目录扫描、CLI `--help`、状态机状态与转移边枚举，画出角色表、状态转移表、命令入口表和核心产物链。覆盖度按这张关系表对账。
2. **精读 2–4 个轴心工件建证伪锚点**：亲读主状态机定义、核心门禁入口、最重的一本执行手册全文，掌握核心机制的真实骨架，确保子代理回传后能快速顺藤摸瓜验真伪。

## 2. 角度设计与模型配对

按被审对象的结构选择切法，复杂体系直接叠加：

### 菜单甲：消费者首次接手镜头（适合多角色各读各的手册体系）

让每个 worker 扮演一个**首次接手该阶段、仅拥有该角色合法可见上下文**的执行者（如各阶段 worker、主调度者），从拿到输入一路走到提交收尾，专门抓“读完不知道怎么干、字段靠猜、refer 落空、首现无定义”。另设术语专项、引用闭合专项与历史残留专项。

### 菜单乙：跨组件关系轴（适合提示词 × 状态机 × 门禁代码 × 测试四层咬合体系）

| 轴 | 核对关系 |
|---|---|
| W1 规范语义 | 同一规定的主体、适用条件、时点、约束强度、单内冲突与跨状态责任承接 |
| W2 工具环境 | 指令原文 × 实际调用形状 × 接口解析与权限白名单；成功/拒绝/无变化/部分完成四类返回的后续动作 |
| W3 状态转移与门禁 | 每条转移边要求先完成的动作 × 硬门实际检查 × 门写盘副作用 × 软审拿到的材料 × 拒绝留态后的重试出路 |
| W4 父子派遣 | 父要求 → 派遣注册载荷 → 模板展开后的真实上下文 → 子规定 → 返回与完成判定 |
| W5 产物消费 | 同一产物从生成、接收、规范化、合并、发布到下游读取的字段、标题层级、空值含义与版本身份 |
| W6 机制交互 | 多机制共享同一状态或文件时的共同命中冲突、事件顺序敏感点、故障恢复与失效传播链 |
| W7 要求落实 | 已确认裁决与设计承诺在提示词、源码、生成配置与已部署快照上的承接账 |
| W8 测试区分力 | 转移边与拒绝分支覆盖账、断言与现行实现对照、fixture 吞参数/mock 吞校验/汇总吞失败等假绿路径、被删测试的验证真空 |

**高密度主轴**：**W3、W6、W8** 是产出机制级死结与假绿密度最高的三条轴。

**模型路由与弱点补偿**：
- 派前先查 `provider_usage` 确认额度余量，选高余量池扇出。
- **W3 / W6 / W8 及精度轴**优先派给强推理模型，要求每条高危结论附代码执行路径或最小探针。
- **长文语义 / 角色镜头 / 要求账**可派给擅长自然语言长文扫描的模型；自然语言模型容易把“两处措辞不同”直接报成“机制冲突”，因此在任务书中**强制要求贴出两端原文，并写出两种读法各自导出的具体动作差异**，用证据格式收紧精度。
- **自由探索**：各 worker 互盲并发、不设“已知问题排除清单”；多路独立撞上同一问题是交叉信号，去重归主代理。

## 3. 扇出派发与运行回收

- **输出隔离与持久归档**：只读收集共享工作区，每个 worker 写入各自独立路径；回传后主代理第一时间把原始报告拷入工作区持久目录（子代理默认输出目录受会话保留期管理，且后续修复阶段需要直接读取原始报告）。
- **十分钟最小实例取证**：鼓励 worker 借用仓库现有测试 fixture 在 `/tmp` 构造最小真实调用链，抓取真实回执和任务包原文逐字段比对文档承诺；**10 分钟内构造不通即转为静态代码路径推演并注明缺口**，防子任务为搭环境卡死。
- **超时先从 transcript 打捞**：子任务超时后，先检查其 session transcript 末尾的 `write` 工具调用参数——实战中常有整篇报告已生成完毕、仅在最后一步超时的情况，直接提取落盘即可进入核实；确属半途卡死再缩小范围重派。
- **长耗时 bash 分诊与 steer 时机**：导航消息（steer）需等当前工具调用返回后才生效。发现 worker 长时间停在 bash，先查看其当前运行命令（区分正常长测与死循环），发出的收尾 steer 直接给出立即停机指令：“当前命令结束后停止扩展验证，将外部环境缺口记入待补证项，立即写盘收尾”。

## 4. 主代理核实与归并

子代理报告只是候选池。主代理对每条准备收入终稿的发现亲自核实：

1. **查源头**：打开候选指出的两端文件与门禁代码，走读完整条件分支和合法补救路径；高危死结亲跑最小内存探针或 CLI 调用确认。
2. **辨同源与排误报**：多个 worker 引用同一段错误前提只算一份材料；经查证现有上下文已消解或存在合法出路的候选，记入“排除记录（附反例证据）”防后续重复排查。
3. **合根因与按 QPDI 归位**：同一根因在多个角色面暴露的症状合并为一条，保留全部受影响位置；纯落实偏差归实现层（I），规则遗漏归拥有该规则的设计层（D），跨分支共享冲突归公共责任层。
4. **列阴性覆盖账**：对照第 1 节的关系表，把已逐项核过且确认一致的面（如 CLI 参数矩阵、镜像文件同步、refer 链闭合）明确列出，连同待补证项一起交代清楚。

## 5. 产出决策项与非决策项（写给人看的报告）

两份报告的分界标准是**是否存在改变契约或行为边界的真分叉**：

- **决策项（`DECISIONS.md`）**：存在两条以上合理修法，且不同选法会改变对外契约、角色权责或允许的行为范围。
  - *正例*：返工报告是强制覆盖全部图邻居，还是只列返工起点由后续传播链自然负责；分流态软审拒绝后是保留原报告快照并豁免门产物，还是回滚门产物。
- **非决策项（`NON-DECISIONS.md`）**：目标与契约已经确定，修复方向唯一，或虽有几种技术手段但服务同一既定目的。
  - *正例*：契约已定“出态时磁盘图库即为完整接受代”，在出态门做检查点落盘即可直接解决，归入非决策项由实现者直接完成。

### 人话写作铁律（前因后果自足）

负责人看报告时手头并未打开被审源码或状态机文件。严禁写成“`A_PREPARE` 写‘沿用’ vs 门禁拦截”这类只有载入全套源码的 AI 才懂的速记黑话：

- **每条决策项必须按自然语言讲清四步**：
  1. **流程位置与角色动作**：这是整个流程的哪一步，当时哪个角色正在干什么；
  2. **原本设计意图**：这一步原本为什么设置这条规则或这道门；
  3. **冲突现场与后果**：现在哪两处规定或先后动作撞在一起，一步步怎样把流程卡死或把材料毁掉；
  4. **选项、边界与倾向**：列出可选方案、各自的连带影响，以及主代理推荐哪一个和理由。
- **每条非决策项用一句完整的人话写全三要素**：在什么场景下、哪两处对不上导致什么具体问题、准备怎么修；按执行链/角色面/文档卫生分组，方便负责人快速扫读。

## 6. 裁定后的隔离执行与跨域收口

负责人拍板后：

1. **隔离工作树并行修复**：在独立 git worktree / 分支上按互不重叠的文件责任域（如门禁与运行库域、提示词与手册域、测试与 runner 域）拆分 2–3 个修复 worker 并行处理；worker 只改文件、零 git 操作，由主代理统一检查 diff 并提交。
2. **主代理跨域对账**：并行分支合并时，专门核对“门禁改了新报错文案 × 测试仍断言旧文案”“新门禁加了不变量 × 老测试 fixture 缺该初始字段”这类跨域接缝，逐一补齐 fixture 与断言。
3. **真实回归与分支对照**：跑全量定向测试并核对实际选中数、跳过数与退出码；長时测试用一次性后台脚本任务配合终态唤醒收取结果。遇疑似环境失败，在干净基线工作树跑同一命令做对照确认。
