# 内部一致性审查

审查对象：
$ARGUMENTS

目标是让同一执行者在同一合法情境下，沿规范、输入、工具和接收流程得到一致且可执行的动作。审查围绕具体使用点展开：谁在何时读到什么、据此做什么、结果由谁怎样消费。

主代理确定范围与有效要求，子代理沿不同关系收集候选，主代理逐项核实后向负责人交付判断。派遣细则见[参考模板](../docs/internal-consistency-audit/references/dispatch-prompts.md)，实践演进见[历史记录](../docs/internal-consistency-audit/history.md)。

## 1. 确定对象、依据和权限

开始时恢复负责人当前目的，说明本次要支持的判断与交付形式。记录审查版本、工作树差异、相关部署版本，以及其他正在编辑的文件。

以负责人明确要求、有效裁决和所属设计合同建立判断依据；按来源、适用对象和生效时间处理新旧关系。实现提供实际行为证据；历史说明提供当时的理由与取舍。对来源有分歧的候选，先列清决定判断所需的具体材料。

默认执行文件阅读和静态分析，写入指定报告目录。隔离实验、运行测试、修复、提交与发布分别采用对应授权。实验计划写明自有资源、输入、预期观察和结束条件。

主代理先读取入口与关键合同，建立足以接住子代理发现的对象地图：

- 角色、状态与合法进入条件。
- 指令、命令、权限和回执的对应关系。
- 输入、产物、接收、合并、发布和下游消费的交接关系。
- 多个机制共同依赖的状态，以及成功、拒绝、重试和恢复分支。

覆盖范围从这张关系表推出。文件清单与worker数量用于安排阅读工作，检查完成情况按具体关系和条件分支登记。

## 2. 选择派遣角度

优先按关系分工：

| 角度 | 核对关系 |
|---|---|
| 规范语义 | 规定的主体、条件、时间、约束强度与跨状态责任 |
| 工具环境 | 指令原文、实际调用形状、接口、权限与返回解释 |
| 状态转移与门禁 | 转移前提、产物要求、实际判据、评审材料与失败后续 |
| 父子派遣 | 父要求、注册载荷、展开后上下文、子规定与返回约定 |
| 产物消费 | 同一产物的生成、接收、规范化、合并、发布和消费 |
| 机制交互 | 共享对象上的共同条件、事件顺序、恢复与失效传播 |
| 有效要求落实 | 裁决的来源和适用范围，以及工件所处变更阶段 |
| 测试区分力 | 被声明覆盖的行为、实际执行路径、断言及结果汇总 |

对象以多个角色分别阅读为主时，可采用消费者视角：执行者、调度者、评审者各沿自己的完整使用路径阅读。术语、引用链和历史文档可作为专项角度；术语候选须指出含义差异怎样影响具体行动。

任务数量随关系表选择。共享边界安排有意重叠，例如产物接收同时由生产者视角与消费链视角核对。主代理说明每个角度的专属责任、重叠关系和保留的判断工作。

各收集任务独立阅读，使用相同的有效要求与部署事实。候选意见分别回传；重复发现保留各自证据，交主代理归并。任务书鼓励自由探索，按实际收到的背景注明独立性。

派发前查询可用模型与额度，按当前能力和成本选型。条件组合、接口精度和机制交互优先使用擅长推理的模型；文档组织与语义阅读可用擅长自然表达的模型。全部任务采用同一证据格式。

## 3. 收集候选

每个任务书写清角色、材料、关系轴、操作权限、输出位置和结束条件。每条候选包含：

> 位置与原话 → 适用情境 → 比较的另一端及证据 → 差异怎样影响执行或判断 → 最小处理方向。

收集结果分三类：

- **证据闭合的候选**：两端材料和触发条件支持一个具体冲突。
- **待补证候选**：列出已取得的关系证据，以及决定判断的剩余材料。
- **表达改善**：现有规则可共同执行，改写能节省读者的具体理解步骤。

每个任务同时交实际检查过的关系、条件分支和剩余范围。发现较多时先交高影响项，再附其余候选，便于保持召回范围。

## 4. 主代理核实与归并

主代理对每个准备收录的候选检查适用条件、原话含义和决定性证据；高影响项直接读取相关来源与完整调用分支。实验在已有授权下按需执行。

报告中的证据用法：

| 材料 | 支持的判断 |
|---|---|
| 规范与有效裁决 | 应履行的义务、适用条件及责任归属 |
| 静态调用链 | 指定前提下的分支选择、数据流与副作用 |
| 函数探针 | 指定输入和替身边界下的局部行为 |
| 隔离端到端实例 | 该版本、配置、输入和执行顺序下的实际结果 |
| 测试运行记录 | 实际选择、执行、跳过、退出码及产物 |

同一来源的重复转述归为一份依据；不同角度分别取得的证据用于交叉核对。核实后按根因归并，保留独有触发条件和各来源位置。被反例排除的候选记下排除理由，待补证项保留其具体缺口。

最后按最初关系表对账：各组件合同怎样组合、哪些共享前提已核、哪些条件仍待核。结论限定到实际审查版本和已检查关系。

按QPDI归位：落实偏差由实现承担；规则缺口回到拥有该规则的设计层；跨分支共享问题回到共同责任层。Sound检查来源与推导，Complete检查已触发义务，Concise收敛重复和陈旧内容，Optimality比较实际存在的更简处理方式。

## 5. 写两份负责人可直接阅读的报告

**决策项**：确需负责人决定目标、语义、责任分配、风险接受或其他保留取舍。每项说明它在流程中的位置、原本用途、冲突情境、已核实依据、可选方向与建议。已有要求足以确定目的时，由实现者选择满足该目的的技术办法。

**非决策项**：依据现行合同即可确定处理方向。每项用一句完整的话交代使用场景、问题和处理方向；按执行链、产物、测试等对象分组。待补证和表达改善分别列在这两份报告的对应栏目。

原始收集材料作为内部依据保存到授权的持久位置，报告内保留可定位引用。负责人最终收到约定的两份文件及必要的状态说明。

## 6. 结束与后续

审计交付时说明已确认的问题、剩余证据责任、实际覆盖范围与负责人需要作的决定。修复和发布沿后续授权执行。

获准修复后，在自有工作区按共同责任层传播变更，再同步提示词、手册、镜像、接口和测试。并行写入采用互不冲突的责任域，主代理负责合并后的跨域对账。回归记录实际执行结果，长任务采用后台运行与终态通知。

审查材料和交付文件沿同一保密范围使用。对外推广方法时保留关系结构、判断依据与纠正经验；案例采用通用角色和字段，历史明确其记录来源和验证范围。
