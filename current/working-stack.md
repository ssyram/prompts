# Working Stack

本轮材料：
$ARGUMENTS

## 目的与Owner

WS (Working Stack) 保存owner正在完成的工作与形成的认识：目的为何仍成立，当前据什么推进，哪些点已对齐/仍有缺口，谁欠什么，下一步谁能做什么。它不是AI内部todo、聊天流水、完整项目设计或完成证明。接手者应能从已有材料继续，不重新推导已经形成的关键理解；填齐栏目不等于达到这个目的。

Owner是本层授权范围内有权确定目标、裁决取舍与判断完成的主体，不由谁执行、调度或写文件决定。人类主导时用户仍是owner，AI协助；明确委派的局部任务中主线程AI可作本层判断。技术执行授权不自动包含范围变化、发布或替上层验收的权力，不能自认owner反向授权自己。

人类owner的要求、提问、纠正、复述与选择是协作依据。用户问“边界是否覆盖”不是错误信念；AI混答对象/版本造成的困惑先纠正自身。明确说未读才记未审阅，无反馈记未知。具体对象上A/B已对齐、C仍有疑问须有来源；不评分“理解80%/完全理解”，不从沉默、继续推进或一句“行吧”推全文理解/整体接受。

AI交付不是owner已经取得可用认识，待owner决定也不能掩盖AI尚欠的解释、反例或材料。主动帮助形成可用于判断的依据，不要求人类理解全部底层细节才能授权；简单执行和授权内技术自治不强制加人工审阅关卡。

## 工作语义：两种维护方式共用

根帧保留本层目的和边界。帧是需要独立继承的目标/理解/裁决上下文，计划是帧内工作；不因工作量大或每次工具调用默认push。确有独立目的与回程才建子帧，独立工作线才另建栈。

每帧有稳定不重用的ID和唯一上帧。沿实际parent恢复责任链，不按文本邻接或严格LIFO猜父链；同父多个未结束分支为para。注意力至多一个TOP，也可全暂停；TOP/PAUSED不表示进程运行/停止，后台回填不自动抢焦点。改挂改变当前责任，不重写原PUSH历史，也不自动转交owner权限。

目标、执行事实、认识依据和行动许可分别判断，不压成一条进度等级。原进入原因保留在来源/PUSH，后来为何继续写到当前所属内容。只将改变owner理解、成果边界或下一责任的信息记入WS，瞬时计数与内部流水留已有运行evidence。

新信息改变了目的、继续理由、依据或边界时，更新其所属内容及真实受影响的父计划，不只在最新子帧append。当前项被替代就修改当前项；必要的历史成果、反例和推翻理由保留，不向每层祖先抄录。

Done对应本层原目标及授权内owner判断，多个目标全部满足才结束；计划全勾、报告已交、结构绿不证明用户验收。技术目标可由受托主线程据证据完成，用户验收若属目标则须明确验收。一支达成不自动完成父/兄弟。暂挂用Paused；owner取消/失效的未达回合用Expired并保留成果、未完义务与承接，不伪称完成。

误关闭按证据Correct，保留原判断/理由与未完责任；正常新要求不伪装成旧帧复活。关闭时达成记录保存当时口径，不能以动态的“当前理解”note倒写历史验收。原则须有本层效力来源，重要事实或AI命令句不自动成为规则；退出时逐条处置为局部保留、上移承接、推翻或转存结果/备注，过期不自动上移。

## 优先作为working-stack工具的使用者

官方仓库：https://github.com/ssyram/working-stack 。二进制可用且适用于当前文件时，优先用同一工具查询/更新；初次读`working-stack doc ENTRY`，需要语义协作读`working-stack doc owner-collaboration`，操作格式读`working-stack doc ai-manual`或对应help。完整教程随仓库/安装包的skills/working-stack/references/practice.md提供。

```sh
working-stack STACK show context
working-stack STACK show context ID
working-stack STACK get 'T-02.plan' --json
working-stack doc path-edit/README
```

STACK可以是托管名称（.working-stack内自动限域Git）、独立YAML/JSON文件或MD路径。沿既有文件/存储约定维护，不为了使用本方法另起第二份状态账。工具/文档不可用不自动授权安装、联网部署或启动Web；无需工具也可按下一节维护MD。

先理解description导览，再对照本次委托、最新裁决与实际执行材料。show context是已录入快照，不自行判继续理由、owner理解或批准；必要时按路径补读，不默认全历史重读。无焦点不自动选择，推荐方向不等于已经切TOP。

变更提供有信息量的reason，用已有push/pop/pause/resume/update及get/set/insert/remove/move完成。复杂计划可用字符串set改正文而保留progress/children/fork；备注按标题覆盖，长材料用单份note。多帧可编辑YAML候选后apply，当前apply无提交前preview；顺序多次调用不是整批事务。命令格式以实际工具文档为准，不猜--result等不存在的参数，不增加别名。

工具拥有树/焦点显示、校验、事件时间与canonical重印，使用它时不另手写日志或派生标记。MD写操作会整体重印，结构化引用保留不等于原字节排版一致；JSON请求与JSON文件codec能力不可混为一谈。参数/结构失败先定位，不改走手写以绕过失败。

用户明确要直接编辑MD，或二进制不具备使用条件时，可使用手工方式；不要在native文件上套MD格式，也不对同一栈同时维护两份权威。工具日志只记原因/变更字段，不自动备份全部旧正文，必要旧依据留既有工件/Git或适当正文。

## 无工具也自洽：直接维护MD

遵循已有MD文件及owner约定；新建时可用以下结构。导览是#标题后的段落，说明本栈范围、owner授权与材料位置，不另抄动态进度。共享内容可按名称存note；普通文字指路不假装已展开/核验，引用的必要原文需实际读取。

```markdown
# 工作线名称
本栈承接什么目的、owner是谁及保留边界。全局材料在哪里。

## 栈状态
[W-01] 根责任
- [W-02] [TOP] 当前上下文
- [W-03] [PAUSED] 保留旁支

## [W-01] 根责任
- 上帧：无。
- 来源：实际委托与授权来源。
- 弹帧目标：完整本层目标与达成条件。
- 计划：
  - [in_progress] 当前责任，必要时写已有依据与下一责任。

## [W-02] [TOP] 当前上下文
- 上帧：[W-01]。
- 来源：为什么进入这个独立上下文。
- 弹帧目标：什么证据/裁决闭合本目标。
- 计划：
  - [in_progress] 当前步骤；不以AI执行盘点替代owner工作。
- 已得结果：具体成果、适用范围及依据；没有则不编造。
- 外部执行事项：实际副作用；只读不算副作用。
- 备注 · 当前协作：对象/版本及来源支持的对齐/缺口与双方下一责任。

## [W-03] [PAUSED] 保留旁支
- 上帧：[W-01]。
- 来源：旁支为何成立。
- 弹帧目标：本支达成条件。
- 暂停原因：正在等谁的什么输入/决定，如何恢复。
- 计划：
  - [blocked] 实际等待的责任。
```

这是填写示例，不是所有字段的强制清单；来源中的委托必须真实可定位。树只列未退出节点，空时写“空”，只在兄弟分叉用缩进/树枝。父关系以正文上帧为准，概览与其一致；关闭帧保留原ID放在后面，不删除历史、不改写原目标凑成功。

手工push新ID，记录明确父责任与进入原因，更新唯一TOP及必要暂停原因；resume旧暂停ID而非重新push。计划调整仍属当前帧时直接改正文/进度，不默认另建planning帧。改挂先明确当前归属并保留原进入记录。暂挂仍open，不能据暂停就结束父帧。

退出时在“达成情况”写done或expire、整体结果及对原目标的对应/证据；只写实际成立的正向、反向、额外收获和残余义务，不凑分类。反例可完成判真假，不能冒称证真。保留必要原则处置与回程，未达且无取消/承接决定时继续计划而非假pop。

手工维护需要在所属帧“### 帧变化记录”追加PUSH/UPDATE/PAUSE/RESUME/POP或有据更正；时间用真实带时区记录时刻，不能当用户消息或旧事件时刻，旧记录缺时间不补造。内容改到哪里、为何改由简要说明/定位承接，不重复整份正文、不为无变化写日志。存量旧帧不追铺空历史；本次实际变化时建立记录。工具路线的自动日志职责不转嫁给手工之外的调用方。

先读原文件再改，不整份重生覆盖已有材料。提交只包含本轮有据修改的文件，不用git -am混入他人改动；没有修改不提交。已有结构检查脚本按实际路径使用，它不判语义/owner批准；没有检查脚本不因此发明门或阻塞正常维护。

## 复杂项的人类状态：记录协作，不评分

复杂plan保留任务名称，在正文附短说明，例如“报告v2，据消息H12：A/B已明确对齐，C待AI解释；仅批准试用，采用仍待owner裁决”。长说明或跨项判断放所属备注/单份note并定位；H12必须真实存在，不因模板创造来源，不要求每项填理解状态。

成果事实与证据独立；最新人类状态放仍负责该判断的帧备注或note，按语义标题替换，例如“比较报告｜人类协作”。关闭时达成记录保持当时依据；后续新反馈更新当前责任，确为误关才Correct。用户不必理解所有细节才能批准，AI也不能以“待用户”隐藏欠项。

本层owner是自治主线程时同样记具体采用的前提、未闭合点与下一责任；只在超出委派或遇保留裁决时上交，不强制每个技术项人审。采用的声明不认证结论客观正确。

## 复工呈现与回填

工具路线从context/必要查询取材；手工路线从导览、实际父链和相关正文取材。呈现应让owner知道整体目的、当前焦点为何服务它、已成立/尚待判断的具体依据、各方未完责任和可采取的下一动作；不要只给ID/任务行，不把最新记录当最新意图。无法支持的认识或权限明确未知。

多工作线分别给出其目的与当前责任，保留唯一选定焦点及相关暂停旁支的恢复条件；已退出内容按所属线保留紧凑成果，只在当前理解需要时展开，不混成全局聊天流水。具体输出形式服从owner约定，不强制每线填同一套表。

获授权维护时，把本轮形成的理解更新到所属内容和受影响父计划，使下一次复工不重新推导；只请求理解/建议而未授权落盘时，报告推荐变化，不替owner切焦点或修改文件。纯讨论无变化不制造更新，也不因使用本方法追加审查、实验、后台工作或新的业务执行权限。
