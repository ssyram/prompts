# 对外技术报告写作

写作要让目标读者完成本报告应支持的理解或判断。报告的高价值交付是在严谨基础上，对本次任务规定的对象和范围作出**绝对判断**：先核实决定其成立或不成立的事实和前提，完成必要推理；再把已经取得的结论交给读者。这里的“绝对”不扩大到任务外，也不把范围内已经成立的判断退成模糊保留。先把所需信息和联系交代正确、充分，再减少没有当前贡献的表达负担。

默认采用以下写法：尽早让对象、用途和范围可辨认；直接写对象、动作、关系、条件和证据；用核心办法和贯通案例收拢细节；不用空泛形容词堆气势。这个默认不能压过已确认事实、明确委托、文类用途或实际读者需要。

## 怎样使用本技能

下面的骨架、改句动作和例子帮助你完成写作，不是要求每篇报告介绍这些写作方法。任务与事实规定必须完成什么；推荐提供可直接采用的写法，但不唯一决定句子或章节。未列场景仍按实际任务构稿，不以套中模板或勾完问题代替判断。

这些工作可以往返进行：写例子可能暴露机制缺口，核对材料可能要求改结论。章节顺序是使用指引，不是不可逆的写作过程。

## 1. 先取得本次报告要完成的事情

### 从真实来源恢复任务

阅读用户委托、后续纠正、交付用途、当前事实材料和用户指定的样文。样文只用于学习对象、条件、结果和证据如何被交代；不照搬它的术语、数字、结论或章节。

先在内部说清：

> 读者读完后，需要能够理解或判断哪些具体事情？

这句话要能发现真实遗漏，并确定每项判断的对象、范围和成立条件。例如，“让人理解方案”太宽；“让负责人判断用户能否定制规则、哪些结论已验证、哪些仍是设计目标”能直接约束正文。对需要作出判断的事项，继续找出决定答案的事实、定义、比较基线和推理关系。

委托和已接受纠正决定要完成什么说明和判断；核实材料约束能作哪些主张；读者已有认识、文类与使用场景决定需要解释到哪里。这些条件共同约束文稿，不是可以相互抵消的排名。标题和主动主张也要据此校正：无依据的承诺应更正，不能因草稿已写过就增加任务。事实已经齐备但推理尚未完成，不是新的事实缺口，也不是把判断交回用户的理由。

不要从现有标题、目录或几段顺畅文字反推“这就是本文原本要交付的全部”。已有稿件是待组织的材料，不是任务的唯一裁判。

### 分清缺口和选择

- **事实、规则含义、范围、结果、证据或授权缺失，且影响本次必要说明或判断：**先确定它阻断哪项判断，以及在本次授权范围内怎样补足。可补足的，回到权威材料完成核查；事实已齐但还没完成比较或推理的，完成推理。确实无法取得材料或授权时，指出缺什么、为何阻断何种判断和造成的后果；不要用模糊保留把未完成的核查伪装成结论。
- **事实和任务已足够，只是有多种开头、章节、图表、例子或句式可选：**由作者比较、选择或组合。模板没有匹配项，不是把表达工作交还给用户的理由。
- **原稿与权威材料冲突：**按权威材料更正。保真不是保留草稿错误。
- **需要新的表达来说明已有规则：**可以重组材料、构造忠实的说明例子和图示；不得借此新增未决定的能力，或把目标写成已测得结果。

### 把核查变成可负责的判断

调研、版本能力或完整性报告不能只列已经拿到的材料。先由调查问题确定应查对象和相关性，再界定发布主体、材料类别、日期和版本。例如，官方说明点名所用平台，就沿该平台的论文、接口和操作文档核查；参与者由官方介绍或本人参与说明确定，再调查其与本问题有关的公开材料。

回顾性报告先读取并核实完成记录，写出实际完成的工作及由此确认的结论，不能一直停在“如果完成，就可以这样写”。来源渠道覆盖、材料清点、正文阅读、源码核查和历史清点各有对应凭据。逐项确认完成情况后，再汇总总体保证；每项仍说明完成的是哪种检查，不能把路径清点升级成全部源码审读。原始链接、版本和完成记录放在索引或附录。

**说明场景（给定事实，不是本次调查）：**任务是检查V版公开发布包能否用于按原条件复跑。已对照官方发布入口核清该版清单，并检查完清单中的全部12份说明及仓库运行入口。核查确认：按原条件复跑必需的启动配置未发布，也不能从包内信息确定。正文可以写：

> V版发布清单中的12份说明及仓库运行入口已全部核查。该发布包缺少必需的启动配置，无法仅凭这个包按原条件复跑。

前句交付已经取得的覆盖保证；后句报告核查查明的缺项及其后果。实际报告中的对象、数字和结论必须取自本次记录。不能用“已收集材料”偷偷代替应查集合，也不能因为范围外仍有未知而削弱范围内已经成立的判断。

## 2. 由任务构成必须说明的内容

对每项读者需要完成的理解或判断，找出它所依赖的内容。常见内容是：

- 正在讨论的对象、主张、决定或结果；
- 对象之间的组成、输入输出、因果、时序、约束或对照关系；
- 条件、范围、例外、否定和仍未确定的部分；
- 支撑事实、比较、建议或结果的材料与证据状态；
- 需要走通的案例、图、配置、命令或计算。

这些不是每段都必须填的槽位。一个图可以承担多个关系，一段可以同时完成对象定位和条件说明。要求是：读者完成本文任务所需的内容和联系，在整篇报告中确实可找到、可接回。

除了决定是否保留，还要判断内容承担什么作用：它是结论、决定性依据、理解前提、必要限定，还是次要背景。这个作用决定标题层级、篇幅和位置。长表不能因材料多就占据主位；短定义若是后文判断的前提，也不能省掉。比较应当支持一项评价或选择，不只是排列对象；局部改动或案例不能取代它所服务的上层目的。

同时做两种不同的检查：

1. **贡献检查：**这项内容完成了什么当前说明，支持或否定了哪项判断，或为后文提供了什么必要前提？
2. **覆盖检查：**从任务得到的必要内容、关系、条件和依据都已经被交代了吗？

贡献检查通过，不证明没有缺项；覆盖检查通过，也不证明没有多余内容。标题或段落不需要一一对应某项要求，但整篇必须完成所有当前要求。

共享内容不等于应删内容。若一段重述用于确认范围、比较候选、汇合分散信息或让后文有明确落点，它仍有贡献；删掉的是不再承担这些作用的重复。

## 3. 选择开头和正文组织

下面是可组合的默认方案，不是完整分类，也不是不可更改的写作次序。选择依据是：读者现在缺少哪种认识，下一步需要什么才能理解或判断。

| 当前情境 | 优先组织 | 简短骨架 | 何时改变 |
|---|---|---|---|
| 需求已共享，但提出的新对象尚未定位 | 对象类别与用途 → 使用者能做什么 → 核心办法 → 贯通案例 | “X 是一种……，用于……。使用者可以……。下文以……说明它怎样作用。” | 类别会误导，或读者已经充分知道对象时，先从任务、对比或情境建立位置。 |
| 问题、情境或本次处理范围尚未共享 | 必要情境/问题 → 本文处理范围 → 提出的对象或办法 | “在……情形中，现有做法无法……。本文只处理……，提出……” | 读者已知 WHY 时，压缩无当前作用的背景，尽快说明本稿处理哪一部分。 |
| 对象已知，本文主要支持一项有依据的判断 | 带范围的结论或建议 → 决定性依据 → 方法、条件和限制 | “在 A 条件下，建议 B，因为……。下文说明比较口径和限制。” | 若前提可在本次授权内核实，先核实后作判断；若具体材料或授权确实不可得，说明它阻断的判断，不用“有限结论”掩盖未完成的核查。不能伪造结论，也不能擅自换成另一项任务。 |

若这些方案都不合适，先写出读者缺少的关键认识和本文要完成的判断，再组合或构造新的组织方式。只有缺事实、目标或授权时才澄清；仅仅缺现成模板时不暂停构稿。

上述默认体现在每种情境的具体表达中，不是在这些情境之间强选第一行。需要对象定位时，优先直接给类别、用途和使用关系；需要判断时，优先直接给带范围的结论及依据。不要用“X采用Y”让读者猜对象身份，也不要在对象已知时为套模板重讲定义。

**示例：需求已共享，新方案需要定位。** 采用Tool Auth Lang的设计设定：用户能定义识别、构树、标签与审核规则，并复用内置套装。若读者已知动机，本段要介绍这一语言方案，开头可写：

> Tool Auth Lang 是一门工具调用审核规则语言。用户用规则识别调用结构、组织子树、添加标签和审核要求；常用工具提供可复用的规则套装。

**示例：对象已知，任务要求选择。** 若给定材料为“A只检查语法，B还检查业务约束”，委托限定“仅按业务约束检查能力选型”，可写：

> 按本次业务约束检查的要求，应选B；A只检查语法，不能满足这一要求。此结论没有比较两者的性能或成本。

第二例不能为了明确对象，就改成从“A和B都是检查工具”讲起；也不能把有限比较扩大成“B全面优于A”。

正文可以按对象与作用、问题与回答、条件与结果、时间过程、证据与结论或方案对比组织。不要因为某种结构在别处成功，就强行把所有材料塞进同一种输入—处理—输出或 WHAT→WHY→HOW 模板。

## 4. 让正文、图表和案例共同完成说明

每个部分都应承担一项当前说明任务，或为后文可追踪的任务提供前提。写作时明确：

- 本段要让读者知道、比较或判断什么；
- 理解它需要哪些已知对象、关系、条件和证据；
- 这些内容由正文、图、表、命令、配置、案例或引用中的哪一项承担；
- 删掉、合并或换位后，读者是否会被迫补做作者应提供的解释。

例如，一段要解释文件权限标签如何生效，仅写“标签自动附着”不够。若材料已确定“识别文件引用 → 按上下文解释路径 → 匹配配置 → 标记节点”的过程，并规定写访问遇到ReadOnly要拒绝，就把这些关系写出：

> 规则先识别命令中的文件引用，再根据执行上下文得到路径。路径匹配用户配置后，对应节点获得配置指定的权限标签。后续检查结合访问方式和标签判断；例如，写访问命中ReadOnly时拒绝。

这是补足材料已有的机制，不是由“自动”二字猜出机制。引言若只需概括能力，则未必需要同样的展开。

案例要走通报告的关键链：前提或输入、规则/机制、对象关系、条件分支和结果。图、命令、配置和正文互相指向；图中标识、变量、路径、单位和条件与正文一致。

区分下列状态：

- **设计/目标：**计划怎样工作；
- **配置/规则：**已给定的限制或输入；
- **观察/结果：**在已说明范围内实际得到什么；
- **证据：**什么材料支持这一观察或建议；
- **限制/未知：**当前材料还不能说明什么。

案例可以说明规则怎样被理解，不能自动证明覆盖全面、性能良好、运行安全或结论适用于所有输入。若写案例时发现前文没有交代一个关键关系，回到前文补对象、条件或依据；不要只给案例加补丁说明。

## 5. 检查修饰表达，写清它实际说明的事

**不按词性决定删留；每处修饰表达都须说出本段需要的内容。** 把它与被修饰的对象或动作一起读，先说清：加上这处表达，读者比不加时多知道了什么？例如适用于谁、在什么条件下做什么、为了什么目的、比哪个对象快多少。再对照材料确认这项说明成立。不能只用“有信息、直接、specific、规定性”一串评价词代替这些说明。

优先写谁对什么做什么；条件、结果或证据状态的区别影响理解时，用分句、关系词或表格显化。保留行业术语、代码名和必要概念。读者未必知道的术语、或本稿赋予熟词的新角色，要及时说明；已有可靠共同认识的内容可以直接使用。对同一对象使用同一名称，区分方案意图、配置、检查结果、观察结果和运行效果。

确认修饰指向哪个对象、否定哪项主张、比较的基线是什么；若存在会改变判断的多种读法，先从材料确定含义，不能选一个方便的解释直接改写。

按发现的问题选择改法：

- 保留名称和含义稳定的技术术语；不以“词块熟悉”为理由保留不能直接说明内容的修饰串；
- 范围、目的、条件、程度、关系或证据状态已经说清，就保留。例如，`仅在提交前检查配置`限定检查时点；`为确认发布包能否复现，团队核查了固定版本和构建脚本`交代核查目的。不必因为用了状语而拆句；
- 含义必要，但读者仍须猜修饰词具体指什么，就把含义写出来。例如，`对脚本进行高强度审核`应说明检查哪些行为，见下表。若多个意思压在修饰串中不能直接辨认，分别说明；不是换位置后继续堆叠；
- 比较或评价有依据时，写出当前任务需要的比较对象、条件和依据；
- 材料已确认是目标的内容，按目标表述。关键事实或含义无法确认时，查证或明示缺口；不能通过“降为目标”自行增加目标，也不能删掉任务要求来消除缺口；
- 不承担当前说明作用的造势，删除。

改后重新核对对象集合、条件、范围、结论强弱与证据状态，并检查修饰改写是否同时遗漏原稿已有信息或放过原稿本来就缺的必要内容。局部违反事实或范围要求可以直接判定该处需要修正；局部都正确仍不证明整篇已完成任务。不要另设词性黑名单、句长、名词数量或总字数指标代替这些判断。

| 不足写法 | 根据材料改写 |
|---|---|
| 更自然、更灵活地处理权限 | 用户可以定义调用识别、子树组织、标签和审核规则，也可以复用常用工具的规则套装。 |
| 对脚本进行高强度审核 | 审查者读取指定脚本，检查规则要求的文件修改、凭证外发或任务无关操作。 |
| Writable 文件允许操作 | Writable 只表示这项写检查通过；整次调用还须满足其他适用规则。 |
| 其余情况统一审查 | 任一规则拒绝时，不启动AI Review；没有拒绝但还有待审要求时，将这些要求交给一次AI Review。 |

表中改写使用已给定的Tool Auth Lang方案设定，不是运行效果测量。换项目时回到该项目的规则、事实和证据，不照搬能力或判断。

## 6. 从整篇报告的位置核对

交付前回到第1节得到的任务，而不是只检查局部句子：

- 读者能否看出本文介绍什么、要完成什么说明或判断、适用范围在哪里？
- 全部必要内容、关系、条件、证据和限制是否已经交代并能接回？
- 本文是否真的回应了明确要求和主动声明，而不只是列出相关话题？
- 读者需要推理技术本身，还是作者遗漏了指代、前提、因果桥、比较基线或证据状态？优先修复后者。
- 命令、图、表、变量、引用、数字、否定和正文是否一致？引用是否仍支撑对应主张？
- 设计、实测、估算、观察和未知是否保持各自状态？
- 这次删改是否让条件、范围、证据或必要关系悬空？若会，撤回删除或补足说明。

可以回读、核算、比较和质疑技术本身；目标不是让读者零推理或永不回看。目标是不要把本稿本应完成的解释和判断偷偷转移给读者。

交付文稿和必要的变更说明。对本次要求形成的判断，交付已经核实的结论；已查明“公开材料缺少某项条件”本身也是结论，应说明它的影响。若具体材料或授权缺口仍阻断判断，明确缺口、受影响的判断和后续工作；能在本次授权内补足的，不把它留给读者，也不能把文稿已写完当作结论已有依据。不要为了证明文风改善，额外交付一整套写作方法、虚构的读者测试，或以篇幅、词频下降代替核对。
