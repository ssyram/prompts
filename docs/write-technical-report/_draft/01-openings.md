# Research：英文技术说明的开头、摘要功能与引言结构

## Summary

WHAT／WHY／背景可以保留为选稿时的粗粒度提示，但不是互斥、完备的开头分类，更不等于摘要或引言的修辞功能模型。现有资料支持按读者知识和文类调整入口、合并功能；不支持把“先用途与验收要求”或“首句必须定义所属类别”定为普遍规则。

本路取得四组可直接检查的指南及其中的实例，回答了入口与结构如何区分、短技术说明可怎样启动。没有取得能够比较这些启动方式阅读效果的实验研究，也未取得所检索语料研究的全文，因而不宣称某种入口最快或最优。

## Findings

### 1. 先区分三个层级，才能谈“有多少种”

**判断：首句入口、摘要功能、较长引言结构不是同一分类维度。来源：S1—S4。支持：来源解释；置信度：高。**

- **首句入口**是先让读者看到什么：领域现象、具体问题、对象及用途、方法、结果等。一句话可以同时承担多个功能。
- **摘要功能**是这段独立文本需要交代什么。Koopman列动机、问题、方法、结果、结论，并明确允许合并或跨句表达。MIT列问题、方法、结果、结论，又按描述性／信息性摘要调整重点。
- **较长引言结构**是如何将读者带到本研究的位置。UMass转述Swales的CARS：建立领域、建立研究空间、占据该空间。领域可通过重要性、一般性陈述、前人研究建立；研究空间不仅是“别人做错了”，也包括提问、延续传统、扩展与验证；最后说明本研究目的、工作、主要发现或篇章安排。

因此，CARS的三个move不是“三种首句”，Koopman的五项也不是“五种开头”。它们说明不同尺度上的交际任务，不规定一句对应一个move，更不能直接变成整份短报告的章节模板。这里对CARS的认识来自大学教学改编，未读取Swales原著全文。

### 2. WHAT／WHY／背景：部分重叠，还遗漏了直接入口

**判断：三分法混合了提问角度和信息角色。来源：S1—S4。支持：本任务推导；置信度：中。**

WHAT可能问“对象属于什么”，也可能问“问题是什么”或“发现了什么”；三者在写作功能上并不相同。WHY可能交代现实用途、研究动机或选用方法的理由，也不能视为一个固定move。背景则是相对于当前主张而言的角色：前人结果、领域现象甚至对象定义，都可能成为背景。

故三者既非同义，也非整齐的上下位分类：WHY经常由背景承担，WHAT也可能承担背景或贡献陈述。它们还没有显式容纳“结果／结论先行”“具体情境带入”“问题＋方法一起出现”等入口。与其补成更大的封闭目录，不如记录两个轴：**先给哪类信息；这句话完成什么定位任务**。

对当前案例，“先给正确类别”能修复只说“X采用Y”却不知X是什么的问题；但若读者已经知道X，重下定义未必必要。真正需要检查的是：**读到Y时，读者是否知道它在本稿对象中承担什么任务**。这是一项迁移推导，不是本路文献已验证的认知定律。

### 3. 实例显示组合与边界，而非唯一范本

**判断：有背书的实例并不都以对象定义起笔。来源：S1、S2；支持：直接文本证据；置信度：高。**

**Nature官方标注例。**首句以细胞分裂时纺锤体如何形成的领域过程起笔，而非定义新方法或先讲癌症治疗价值。随后给较具体的背景、尚不清楚的问题，再以“Here we show”引出发现，最后解释发现与更广意义。选择它是因为期刊亲自标注其功能，不是因为发表就代表最好读。其入口是背景现象；摘要功能是由广到窄再回到意义；不能据此推断长引言必须照抄这一段顺序。

**MIT分析的阵风锋检测例。**描述性摘要首句直接把“多普勒天气雷达图像”这一方法与“检测阵风锋”这一问题连起来，并嵌入预警危险天气的目的。它没有先独立定义检测算法，也没有铺一段天气重要性。信息性版本同样从方法和问题进入，继而写算法已开发、部署测试及检测表现。MIT给出的两种版本足以反驳“必须WHAT→WHY→HOW逐项分句”，却不能证明首句塞入越多功能越好。

这两个实例都由写作资料明确选用，背书强于随意挑名篇；但均没有阅读速度或理解率比较。MIT实例含“显著超过”等评价，本路不据此为该措辞背书，也未追查原实验数据。

### 4. 对短技术说明，建议保留四类可组合启动方式

以下均为**本任务推导**，不是文献给出的四分法；可合并，不必凑齐。

| 启动方式 | 适用条件与示意 | 容易误用之处 |
|---|---|---|
| 对象＋类别＋任务 | 新对象尚未定位：“X是一种规则语言，用来表达……。”随后解释最关键组成及相互关系 | 类别过空，如“平台／体系”；把语言说成运行系统；定义后马上堆内部术语 |
| 具体问题／范围＋回应 | 读者知道大WHY，只需知道本稿解决哪一部分：“本文处理……情形，提出……。” | 重复双方已知痛点；制造不存在的研究空白；只说问题不交代本文对象 |
| 具体情境／例子＋一般化 | 抽象问题不易辨认，而一个简单情境能暴露核心区别：先给已解释的行为与期望，再说明方案解决哪一类问题 | 以未解释代码、参数和缩写开场；讲完例子仍不知道它代表什么；例子暗中充当有效性证据 |
| 有边界的结果／建议＋依据预告 | 实测报告或明确决策任务，结果能直接帮助读者判断：“在A条件下，B相对C……；因此建议……。” | 裸数字不写基线；把设计目标当结果；读者连B是什么都不知道就宣布优越性 |

背景不必另立为第五种：陌生受众可以在前两类之前补一两句必要领域定位。Nature提供的是跨学科摘要的充分背景示范，不是所有短说明都应先从行业发展史讲起。具体情境入口在本路没有取得同等强度的实证支持，宜列候选而非默认。

### 5. 想法介绍与实测报告，核心差异在证据状态

**判断：不能要求没有完成研究的说明填入实测结果。来源：S2的Descriptive／Informative Abstracts；支持：直接证据及迁移解释；置信度：高。**

MIT指出，项目完成前的描述性摘要侧重问题和方法，可用于会议提案或进展报告；完成后的信息性摘要重视结果和结论。这支持现有技能“不把设计写成实测结果”。迁移到短想法说明，可以交代对象、问题范围、核心机制、说明性例子和待验证处；例子证明读者能理解规则，不自动证明规则覆盖全面或实际有效。实测报告则须让主要发现、方法范围、比较条件和限制显现出来。

还要分开摘要、短文和执行摘要：摘要通常帮助筛选或预览主文；MIT把执行摘要视为可能替代整份报告的缩微文件，含建议。**短技术说明本身就是正文时，不能仅列“本文讨论A、B、C”就算交付**，也无需另加一套摘要和长引言。MIT的固定字数、百分比分配属于其指南，不宜移植为通用技能硬约束。

### 6. 读者已知WHY：压缩重复背景，不删除定位

**判断：问题重要性已知时可以先写具体问题。来源：S3，Checklist中Motivation及Problem statement；支持：直接证据；置信度：高。**

Koopman明确区分：问题重要性不显然时可先写动机；广泛认可的重要问题上的增量工作，则宜先交代自己处理哪一块。Other Considerations又提醒，非常规发表场合可能需要补领域位置。由此可推出：对已知WHY的指定读者，可用“本稿提出什么／处理哪部分／保留哪项关键约束”完成对齐，不复述需求形成史；面对更广受众，则重新估计背景缺口。

这不支持完全删除用途，也不要求每篇都列委托人的验收清单。双方已知WHY不等于双方已知新对象的类别、范围或技术选择。读者画像目前仍是用户提供的假设，不能写成已测得的理解效果。

## Contradictions：应收窄而非消除的张力

Nature偏向先给跨学科背景；Koopman允许已知动机时先给问题；MIT实例甚至把方法置于句首。这不是谁对谁错，而是受众与功能不同。它们共同反对将一种次序绝对化，但没有证明次序可以任意选择。现有技能“开头写用途与验收要求，再说明方案”因此过窄；“首句一定下属定义”也会成为另一种过窄规则。

## 对技能的少量候选修改

1. 将开头硬次序改成：先确认文类、证据状态和读者已知内容；选能定位当前对象或问题的入口，不重复已知动机。
2. 宏观检查先于词句修饰：首段是否让读者知道本稿交付什么、处理哪一部分；关键细节是否能归属于已交代的对象或任务。
3. 把摘要功能清单当“遗漏检查”，不当句序模板；想法与实测采用不同的证据检查。

不建议加入：全局入口种类数、CARS强制三段式、每篇都要验收清单、每篇都要营造研究空白，以及Nature／MIT的固定篇幅比例。

## Missing evidence / Next steps

没有直接阅读实验、短技术想法报告语料统计或指定读者读者测试，不能据此排列四类入口的优劣。Samraj论文出版社页返回机器人验证，ERIC原摘要抓取失败；只见搜索发现信息，不采用其具体结论或样本数字。经典Swales原著未取得，本报告明确限于大学转述。

唯一值得追加的本地验证是：同一材料做“对象先行”与“范围先行”两个短开头，让目标读者复述对象、任务和范围，检查是否真正减少误解；不必继续搜更多模板凑数。
