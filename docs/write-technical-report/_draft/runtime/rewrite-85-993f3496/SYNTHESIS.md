# 技术报告怎样让读者形成整体理解

这份调研为 `write-technical-report` 的修订提供依据：已有技术分析怎样组织成一篇读者能理解、评价的报告。重点是开头的定位、细节之间的联系、信息是否充分，以及词句如何承担这些任务。

**建议保留的核心不是“先抽象、后具体”，而是：读者读到一项信息时，能知道它在说什么、与已经理解的内容有什么关系、为什么在这里出现。信息先正确且够用，再减少表达负担。**

四路研究已完成。下面区分来源实际支持的内容与本任务据此提出的写作要求。具体技能改法见 [SKILL-REVISION.md](SKILL-REVISION.md)；原技能和 `idea-report.md` 均未改动。

## 1. 先给细节可理解的归属，而不只是给术语下定义

### 1.1 研究材料直接解释了这次开头为什么失败

[源证] Gopen、Swan的科学写作文章用一段分子生物学说明作例子：即使解释了专业词，并补充领域知识，读者仍可能不知道几句话是什么关系、是否矛盾、整段要说明什么。文章随后用温度表、地震段落和实验说明展示，信息的排列与句间联系参与决定读者怎样解释内容。[1]

这支持用户此次区分：**认识X、Y两个词，不等于理解Y在X中承担什么作用。**

本次V08开头先讲“用类型和标签审核工具调用”；V09才明确定位为“工具调用审核规则描述语言”。前者给了审查手段，却没明确这里要介绍的是一门供用户写规则的语言，读者被迫从名称与后文补出类别和使用关系。后来助手将它压成“用于描述规则”，又弱化了明确的类别。

问题不只是“第一句有技术词”，而是开头没有完成当前介绍任务所需的定位。[本例分析；版本见文末本地材料]

### 1.2 什么叫“容纳细节”

[本任务推导] 可以把检查具体化为：

- **对象**：这项信息是在说哪个东西、哪一步或哪条主张？
- **联系**：它与前文是什么关系——组成、输入输出、条件、因果、证据、例子，还是对前文的修正？
- **作用**：读者理解它以后，应当补上或改变整体认识的哪一部分？

这些是检查问题，不是每句必须填满的表单。联系可以在前文建立，也可以在当前句子中及时交代；可靠的共同知识也能提供联系。不要求先画出一个完备分类体系。

“归属”也不限于树状包含。输入—处理—输出、原因—后果、问题—答案、主张—证据，都能组织细节。若强制所有材料进入一种系统分解图，反而会改变内容。

**类别模板是其中一种做法，不是该原则本身。**

- 7月9日对象被定位为程序行为建模引擎，因此代码项目、函数行为输出和工程用途有了各自的位置。
- Tool Auth Lang被定位为规则语言，因此应交代用户能表达什么、规则作用于什么、怎样影响审核判断。只写“输入调用、输出判定”会再次把它介绍成运行中的审核器。

这里的模板是从对象性质及报告任务提出问题，不是用现成空格逼迫作者补造设计。

### 1.3 读者已有认识决定哪些联系可以省略

指定读者原本提出tag思路，是本次可以省去一部分术语解释的依据；但这不等于他知道本稿为tag安排的全部新作用。

[本任务推导] 可以省略共有词义，不能仅凭词义共有就省略新关系。例如，需要说明标签在本方案中标记什么、来自哪些规则、在哪个判断中被使用时，不能用“指定读者知道tag”代替这些说明。

Gopen、Swan讨论的是结构如何提高读者按作者意图解释的可能性，并不保证完全控制解释。[1] 因此，“快速顺序理解”在这里是写作目标，不是每句零推理、全篇零回读的承诺。读者仍可能需要核算、比较或学习技术本身；应减少的是因作者省略必要联系造成的猜测。

## 2. 没有逐一约定，仍需让报告的说明任务可识别

### 2.1 应排除的是“满足每名读者的私人目的”

论文作者确实不能知道每个读者想查什么，也没有与每个人签订委托。因此，不能把“回应指定读者明确提出的验收要求”当成所有技术报告的统一格式。

但从这里不能继续推出“没有事先约定，就没有读者可以合理要求的说明”。读者可以根据文类、标题、摘要和正文判断作者声称要交代什么，并检查实际交付是否与之相符。

### 2.2 理论支持到哪里

[源证] Grice用交流中接受的目的或方向讨论信息充分、证据、相关性和表达方式；共同的近期交流目标不要求双方最终利益相同。他也曾考虑一种准契约说明，但认为其对争吵、书信等情形解释不足，继而探讨目的性与理性基础，并承认论证尚未完成。[7，pp.45–49]

因此，不能把这篇文章说成“证明作者与读者必有根本契约”，也不能反过来说它“否定了一切契约解释”。研究对象是交流合作的说明基础，不是技术报告规范的现成公理。

[源证] Miller区分私人意图与社会可识别的动机。文类让陌生参与者借助共享的情境与话语惯例解释表达；独白因受众较大、不能逐人互动协调，更依赖这种公共约束。[8，pp.157–162]

这解释了为什么没有逐人谈判，书面表达仍能产生预期。它是文类理论的解释，不直接推出“所有惯例都应无条件遵守”。Miller的文类分类，也不是技术对象的属分类；不能从中推出所有对象都必须按输入输出介绍。

还要区分：读者预期下一句怎样出现，是理解过程的问题；要求报告完成其声明的说明，是任务与评价的问题。不能因为两者都叫“预期”，就用其中一项的研究替另一项作证明。

### 2.3 对本技能更有用的表述

[本任务推导] **让目标读者识别本文承担什么说明或论证任务，并提供完成该任务所需的内容、联系与依据。**

任务的具体要求可以来自几处：

| 来源 | 它具体规定什么 |
|---|---|
| 文类与使用场景 | 方案说明、实验报告、摘要、执行摘要各自通常要交付什么 |
| 本文的标题、开头和主张 | 本文主动声明要说明、回答或证明的对象与范围 |
| 明确委托 | 指定读者要求解释哪些能力、达到哪些验收要求、支持哪项判断 |

这张表是本次迁移整理，不是Grice或Miller原文提供的现成体系。作者不能用自行缩小的提纲替代已经约定的任务，也不能用文类惯例去满足读者所有私人愿望。

由此可以分别检查两个方面：

1. **能否理解**：读者能否确定信息所指及其关系？
2. **是否对题**：这些信息是否完成本文可识别的任务？

讲得很清楚也可能答非所问；选中了正确任务，也可能没把必要关系讲清楚。两者都依赖读者背景，但不相互保证。无需争论它们是否严格“正交”，也不应合并成一个无法区分失败原因的口号。

指定读者委托使一般的说明任务变得具体，并可能增加公开论文没有的交付义务。列出关键要求，是让对方核对本稿范围；这不等于反复教授双方已经知道的WHY。读者能据此指出“不符合”，也是对齐成功提供的能力，不必预设他一定赞同。

## 3. 开头没有一个统一的“全部种数”

### 3.1 先分清研究在数什么

本轮材料至少涉及三种尺度：

- 首句或开头首先完成什么任务；
- 摘要包含哪些信息功能；
- 较长引言怎样建立背景、问题或研究空间。

CARS的引言moves，不是首句的三种写法；Koopman的摘要检查清单，也不是五种起手式。本轮只取得CARS的大学教学转述，未以Swales原著全文作依据。[详见01-openings.md]

WHAT可以指对象、问题或结果；WHY可以指动机、用途或选择某方法的理由；“背景”则表示信息相对于当前论述的角色。因此，原三分法可以启发写作，却不是互斥、完备的学术分类。

### 3.2 已核的实际写法

| 来源与文类 | 开头怎样组织 | 能据此学到什么 |
|---|---|---|
| Nature官方摘要示例 | 从细胞分裂与纺锤体形成进入，逐步给具体背景和未知问题，再引出发现及意义 | 为不同专业背景的科学家逐步提供解释新结果所需的背景；不是所有文章都要照抄句数配额。[4] |
| MIT技术写作指南的阵风锋检测例 | 在首句中把雷达图像、检测任务、危险天气预判用途联系起来；项目未完成与完成后的摘要突出不同信息 | 方法可以出现在开头，只要其对象与任务联系同时可理解；不能把未完成项目写成已有结果。[5] |
| Koopman的计算机体系结构摘要指南 | 问题重要性未共享时可先讲动机；重要性已广泛承认时，可以先说具体处理哪一部分问题 | “WHY已知则不重讲”的做法有直接指南依据；清单功能可以合并或跨句表达。[3] |
| 中文科技摘要编辑实例 | 与作者讨论后补出方法、结果范围等，原151字稿改成218字 | 摘要的缺点可能是信息不够，而不是不够短。字数为该文自报；这不是阅读速度实验。[6] |

MIT还区分摘要与执行摘要：前者常供筛选或预览，后者可能替代全文。短技术说明如果本身就是交付物，就不能只列“本文将讨论什么”而不交付必要内容。[5]

### 3.3 可供技能采用的四个入口提示

[本任务推导] 以下按开头首先要完成的任务组织，允许组合，不是对全部开头的穷举：

| 入口 | 什么时候有用 | 需要避免什么 |
|---|---|---|
| 对象定位 | 读者知道需求，但还不知道提出的是什么 | 只贴“系统”这类过宽标签，或只说X采用Y |
| 问题与范围 | 读者需要知道具体问题、重要性或本次处理范围 | 重复已共享的背景，迟迟不指出本文回应什么 |
| 场景与位置 | 直接命名不足以理解对象的职责 | 讲大量场景细节，却不说明本对象在其中起什么作用 |
| 结果或建议 | 已有足够依据，且报告要支持判断或选择 | 给无比较对象、无范围的成绩；给未实测的idea装上成绩 |

“场景与位置”主要是本任务的实践推导，不能与已核指南中的明确建议说成同一证据强度。结果前置也不表示可以省掉对象；对象、条件、结果可以在同一句中建立。

本次Tool Auth Lang仍适合对象定位先行，随后交代关键要求、核心办法及贯通案例。这个顺序来自本次读者画像和说明任务，而不是来自普遍章序。

## 4. 正文组织：先检查该说的信息，再检查怎样说

[源证] 名古屋大学指南把报告结构具体化为：写哪些信息、按什么顺序、各写多少；全文与各部分分别有目的。提纲可以组织主题句、文献、图表；研究与提纲也可以相互调整。它还用“世界—东亚—日本”等示例说明层次顺序对理解的影响。[2]

这比“按理解需要推进”更可执行，但无需把该教学指南中每一项都搬成硬规则。

[本任务推导] 逐段可以采用以下检查：

1. **当前问题**：本段要让读者明白什么？
2. **必要联系**：为理解它，需要哪些对象、条件、因果或证据关系？这些关系已可得，还是作者自己知道却没写？
3. **信息充分**：读完后，读者是否仍必须自行补做本段应提供的解释？
4. **内容归属**：每项材料是在回答本段问题，还是为后文明示的需要提供前提？两者都不是，就移出或删除。

例如，引言说“支持文件权限标签”可以足够；解释标签怎样生效的段落却不能停在“自动附着”。后者需要把文件引用、路径解释、配置匹配和标签落点之间的联系说出来。完整性取决于段落承担的任务，而不是每段都必须自含全篇知识。

[源证] Gopen、Swan的实验改写实例表明，调整顺序仍可能不够：原文缺少处理步骤与测量之间的关系，补入解释后才出现可理解的实验轮廓。另一例在显化动作后又暴露尚未说明的关系与假说。[1，Perceiving Logical Gaps／Locating the Action]

因此，**表达检查可能发现内容缺口；不能把缺口当成文风问题，也不能为了流畅自行编出技术事实。** 有材料就补；涉及未决定的方案就澄清；不为当前任务所需的内容才删。

这里与Occam的关系没有冲突：充分性是裁剪的前提。最少的应是没有必要贡献的负担，而不是机械地把字数压到最低。重要信息可以重复定位，关键例子也可能需要汇合图；是否保留，要看它是否减少本应由作者解决的理解障碍。

## 5. 修饰词的检查需要从“有意义”推进到“关系清楚”

### 5.1 熟词可能组成关系不明的表达

[源证] Biber、Gray区分了指称对象的明确与对象间关系的明确。相同的修饰词可以与中心名词建立不同关系；紧凑短语经常依靠领域知识恢复这些关系。他们对专业读者与新手的讨论是语料描述及功能解释，不是两类读者阅读速度的对照实验。[9，§4、§6]

**词典里有定义，不能证明这句话已经清楚。** 当前技能“这个词说明了什么”的总问句，需要加上：读者能否确定它修饰谁、限制哪条主张、表达怎样的关系？

对专家熟悉的词块，保留压缩可能更好；但词块熟悉不能掩盖本稿新引入的对象、用法或边界。由“学术文章常用压缩表达”也推不出“我们的报告应该模仿所有修饰链”。

### 5.2 不只有删除和拆短句两种操作

[源证] NASA指南肯定 `test design` 和 `review board` 的简洁表达；两者加入其他名词成为一串时，关系可能被遮蔽。其改写例为 `a board for reviewing test design options`，用关系词显化，而不是拆成多句。[10，§3.8.1]

[本任务推导] 先找不清楚的关系，再选最小够用的改法：保留熟悉词块、调整位置、补关系词、说明比较对象、列条件，必要时才拆句。这里不采用NASA的连续名词数量作为中文或跨文类硬上限，也不复制该旧指南其他无关规范。

### 5.3 需要保留的，不只有事实性限定

“可能”调节主张强度，但不能替代事件和范围的说明；“因此”“不过”等可以说明句际关系；有依据的比较、建议和重点提示可以帮助读者判断。它们不能仅因属于修饰或评价而被删除。

当前技能把“称赞、强调、营造气势和替结论表态的修辞”放在“没有提供信息”条目下，原意可以理解为排除纯修辞。第四路报告提醒其中有被读成全面禁止评价、强调的风险。父代理将其收窄为**澄清可能误读**，不把原技能描述成已经明令禁止所有评价。

建议改成：删除只起造势作用、不承担当前说明任务的修辞；保留有依据的判断、必要限定和组织重点，并把其所指与依据说清。尚未实测的目标仍可作为目标陈述，不能因没有成绩就删掉目标，也不能把它写成成绩。

### 5.4 对一句表达可以直接问四件事

[本任务推导]

1. **挂接**：它修饰哪个对象、动作或整条主张？
2. **关系**：它表达的区别、条件、范围、强度或句际关系，读者能确定吗？
3. **依据与用途**：有材料支持吗？是否承担当前任务所需的信息或判断？
4. **改后保真**：删除或改写以后，对象、范围、结论强弱和必要联系变了吗？

不确定含义时，不能让模型挑一种方便的解释填进去。“高效”指延迟、吞吐还是成本，需要来自材料或澄清。AI也可能误读；探索性输入可以保留待整理线索，交付稿不能把解释这些线索的任务继续交给读者。

## 6. 怎样修改技能，而不让技能继续膨胀

核心改动是调整检查顺序与判据：

**读者与报告任务 → 对象及关系框架 → 各部分信息充分 → 词句关系与作用 → 全文核对。**

这不是要求作者单向完成五次独立pass，而是明确优先关系：没有确定本段任务与必要信息，就不能仅凭句子变短判定写好了。

现有技能中的材料不足不编造、目标不降格、方案不冒充实测、关键限定保留、图文一致检查继续保留。新增内容主要落在宏观组织与关系检查；不另立多套方法论，不把全部理论术语塞入技能。

不新增以下要求：固定WHAT→WHY→HOW章序、每段写满所有要素、所有评价数字化、修饰词黑名单、句长或名词串硬上限、强制真人A/B测试或额外review gate。

## 7. 本轮证据够用到哪里

四路覆盖了：开头的信息功能与实例；中日写作指导；理解、连贯与作者读者关系；修饰语及压缩表达。足以支持上述默认写法和技能修订候选，不足以证明一种开头全球最优、所有读者最快理解，或三种语言已有代表性的全面比较。

- 核心来源包括规范性指南、文类理论、语言学语料描述与具体改写实例。它们的证据类型不同，不因有名或来自大学就统一称为实验结论。
- 子报告另有眼动研究及认知实验摘要等线索，保留各自受众、指标和读取边界；本综合不依赖未经父代理核读的实验细节作强结论。
