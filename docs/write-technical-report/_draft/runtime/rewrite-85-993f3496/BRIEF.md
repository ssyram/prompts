## 已确认的方向

目标是通用的、以沟通为目的的技术报告写作技能，默认偏向指定读者已经表达的审美。当前读者任务、真实性和已确认要求优先于默认风格；指定读者偏好应体现在原则解释、默认推荐和例子中，不是被藏在可忽略附录里。

四问仅是症状，不能只给它补缺项。需修整套方法从实际任务到内容要求、从要求到具体表达、从局部检查到整体验收的关系。原则不唯一推出具体写法，并不说明未找到本质；必要要求、操作方法、条件推荐和例子各有作用，不能相互代替。原稿已经写对的事实/证据保护、不降目标、非穷举、可回改等保留，不把这些捏造成缺失。

## 需要真正写成操作的内容

- 从委托、纠正、实际使用场景、可靠的读者已知和材料中，推得读完需理解或判断哪些具体事情，构成相应内容与关系。不能只写“确认任务、清楚充分”。不从现稿标题目录反推任务。
- 区分材料/事实/目标/授权缺口与写法尚未选定。前者按实际影响查证或做最小澄清；后者是作者应承担的比较、选择与构稿工作。模板未匹配不是把工作甩给用户的理由。
- 既检查已写内容有贡献，也检查全部当前必需内容已写。局部检查通过不证明整体充分，也不能把正确硬要求全降成可选提示。
- 原稿有误述时回到权威材料纠正，保真不是固守草稿错误。新表达、组织方式及忠实于给定规则的说明例子可以构造，不能借此增添未决定的技术能力或伪造结果。
- 共享内容仍可能为对齐、对照或整合而需要重述；省掉的是无当前贡献的重复，不是凡已知都删。读者的理解依赖顺序，不等于作者必须按固定步骤写；可以从例子发现缺口再回改开头。
- 在符合任务的写法中，默认倾向明确对象与用途、直接写对象/动作/关系/条件、核心办法加贯通案例、主次可见、少无信息修辞。不要为“通用”把具体做法删空。
- 给开头的常见情境提供适用条件、组织骨架、短例和改变条件：需求已共享而新对象未定位；问题/情境尚未共享；对象已知且本次任务要求有依据的判断。它们不是完备分类，不设三例五问配额；未列场景仍回到任务要求组合或构造写法。
- 正文也要给从任务安排材料、分配说明责任和整合案例的动作，不能只改开头。标题或段落不必一项义务对应一个；要让必要内容和联系实际得到交代。
- 修饰语按所指、关系和当前作用处理。可保留熟词块、移位、补关系词、展开或删除；信息不足先补有来源的内容，必要限定与证据强度不删。不把字数下降当改善。
