# 技术报告写作理论调研

本目录研究如何把已有技术分析写成可理解、可评价的技术报告，并提出 `write-technical-report` 的修改方案。它是当前写作问题的研究入口，不沿用上一轮以完整研发史为中心的复盘框架。

## 先读

- [综合结论与来源](SYNTHESIS.md)：细节的对象与关系、作者读者的说明任务、开头模式、段落充分性、修饰语。
- [技能修改方案](SKILL-REVISION.md)：五步结构、拟新增与替换的文字、保留和排除的要求。**尚未修改实际技能。**

## 四路研究报告

- [英文技术开头与摘要](../../01-openings.md)
- [中日及跨语言写作](../../02-multilingual.md)
- [理解、连贯与作者读者关系](../../03-comprehension-contract.md)
- [修饰语、精确性与阅读负担](../../04-modifiers.md)

这些报告提供材料和候选判断；综合稿记录父代理核读、收窄和取舍后的结论。部分仅核到摘要或教学转述的材料不能升级为原著全文证据。

## 过程与检查

- [用户范围校准](../../RECENT-REQUESTS.md)
- [任务交接](HANDOFF.md)／[运行记录](RUN.md)
- 启动现场及受保护文件hash（原始本地运行记录，未随归档提供）
- 四路完成回执（原始本地运行记录，未随归档提供）
- 子报告hash（原始本地运行记录，未随归档提供）

本轮不修改原稿、现有技能或旧历史总报告，也不追加审查代理。下一步是决定是否实施技能修改方案，不是继续穷举所有写作理论。
