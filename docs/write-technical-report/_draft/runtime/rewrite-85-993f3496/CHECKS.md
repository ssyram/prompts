# 三稿修订核对

核对范围是综合稿、修改方案与技能候选，不是技能效果的实验。本记录区分成稿检查、给定材料试写和仍未验证的内容；结构、链接、文件hash等机器检查结果保存于同目录 `verification.json`。

## 对实际任务的核对

| 要求 | 成稿落点与检查内容 |
|---|---|
| 通用写作能力与指定读者默认并存 | 综合稿§1–2、候选开头及§1/§3：委托、事实、读者情况共同约束文稿；默认用于选择写法，不压过这些条件。 |
| 从真实任务取得必要内容 | 候选§1–2：不从现有目录倒推任务；根据委托和材料确定读者要完成的理解或判断，再找所需对象、关系和证据。 |
| 原则不唯一生成写法，作者仍要完成构稿 | 综合稿§2.3–2.4、候选§1/§3：区分事实/目标缺口与表达选择；没有模板时仍自行组合结构。 |
| 不只检查现稿局部是否有用 | 候选§2/§6：贡献与覆盖分别核对；局部硬要求仍有否决作用，局部通过不证明全文充分。 |
| 推荐不止空槽位 | 候选§3给条件与骨架，也给规则语言介绍和受限选型的成文开头；§4给文件标签机制的完整说明。 |
| 不因简洁丢信息，不借改写增设目标 | 候选§5/§6：保留条件、证据状态与目标；不把无依据主张自行改称目标，未解决的关键缺口须明示。 |
| 保留用户定制与审核语义 | 对照只读的Tool Auth Lang稿件：识别、子树组织、标签、审核与规则套装均保留；Writable只通过该项写检查，Deny不被待审要求覆盖。 |
| 三稿职责分开 | 综合稿给依据与边界，方案给修改对应，候选给执行指令；候选不依赖阅读研究目录，不要求正常报告介绍写作方法。 |

父代理在写作者版本上修正了几处具体问题：不同依据被硬排优先级；无依据内容可直接“降为目标”；歧义短语被自行选定解释；指定读者默认被误写成跨情境偏向同一入口；开头示范只有占位骨架。写作者版本保留在 `writer-version/`，用于区别初稿与交付稿。

## 按候选进行给定材料试写

以下由父代理读取候选后完成，不是独立模型评审、真实用户试读或真实项目数据。材料是本记录给定的写作练习；不以范例通过推断跨任务效果。

### 证据不足不能变成新的目标

**给定材料与任务：**目标要求所有支持负载下响应不超过500毫秒；目前仅记录一次轻载响应20毫秒，没有其他负载证据。要求写出此次测量能支持的判断。

**按候选写出的段落：**

> 本次轻载测量记录了20毫秒响应，低于500毫秒目标阈值。这一次记录不能证明所有支持负载均已达标；现有材料缺少其他负载下的响应数据。

**核对：**保留已有目标、一次测量与负载条件；不给出普遍达标结论，也不凭空添加新目标或实验成绩。

### 入口表没有单列的交接任务仍可直接构稿

**给定材料与任务：**为熟悉任务的维护者写恢复交接。批处理的第1至3片已完成，第4片等待输入，第5片依赖第4片完成；禁止重跑已完成部分。

**按候选写出的段落：**

> 第1至3片已完成，不要重跑。恢复工作从第4片继续：先取得它所等待的输入，完成后再执行第5片。

**核对：**由任务取得进度、依赖与下一步，不因表中未单列“恢复交接”而询问用户该选哪个模板，也不重新解释维护者已知的系统类别。
