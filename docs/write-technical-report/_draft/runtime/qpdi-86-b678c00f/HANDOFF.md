## 最新用户修正

1. “先轮廓后细节”仍过于宽泛。更具体的要求是：**先建立能容纳细节的体系及其归属位置，再放入细节**。只说“X采用Y”而读者不知道X是什么、Y在X中承担什么，不能形成理解。
2. 终极目的：读者每句话能完成局部理解，并将其整合到整体认识中。不是只追求首次出现术语已下过定义。
3. 读者已有认识参与判断。指定读者原本提出tag思路，可能不需重讲tag；其他受众不能无根据地沿用这个假设。用户提供的读者画像与经实测验证的读者反应应区分。
4. 属模板是有用候选，但要正确归类：7月9日对象是程序行为建模引擎；Tool Auth Lang是规则语言，不能因为都有输入输出就把后者介绍成审核运行系统。
5. 对“回应约定要求”的普遍性有疑问。论文作者不知道每个读者的具体目的，也未与其逐一约定。用户不满意仅把指定读者委托归为偶然附加要求，希望考察作者—读者关系中更一般的义务、期待或契约。
6. WHAT／WHY／背景三种入口暂可作候选，但希望查询优秀技术论文、摘要型短文及技术报告的真实写法和写作研究，不能假定只有三种。英文、中文、日文均可查。
7. 已认可“每段回答什么问题／必要信息是否齐备／细节是否承担当前或后续必要任务”的操作化方向，希望查理论支持。
8. 明确认可“信息充分是裁剪的前提”。
9. 对现有修饰语处理仍有疑虑，需用写作理论再审，不预设原规则正确，也不预设应改成禁用形容词、副词。

## 来源与研究纪律

- 不只搜支持现有主张的材料；用户的推导、助手候选、教材建议都可被质疑。
- 优先原始研究、作者/大学/期刊官方材料和可追溯的经典著作。不要拿SEO写作列表或同源转载当独立支持。
- 区分：经验研究、语料/文类描述、规范性写作建议、个别文本实例、本任务的迁移推导。权威不等于证明普适最优。
- 区分首句起手式、摘要的信息功能/moves、长引言结构与整篇章序。不能从某模型的三/五个moves推出“开头一共只有三/五种”。
- 对实例注明选择依据；名篇获发表不等于已证明其开头最快可读。简短摘引并附链接/章节，不大段搬运。
- 对“无显式委托是否意味着无需回应读者目的”“有定义的修饰词是否在句中就一定清楚”等问题，保留推导缺口，不提前裁决。
- 只核到摘要/二手说明就明确标记，不假装读完原著或实验。跨语言、跨文类适用性另列。
- 每路以约4–6项关键来源为起点，足以回答问题即停；不以凑数量或穷尽全部写作理论为完成条件。说明覆盖范围与残余缺口，不追加循环审查。
- 调研阶段允许展开，进入技能时再压缩；不要把所有理论、模板与术语全部塞入技能。
- Web搜索使用 `workflow: "none"`，避免打开交互curator；保留原始链接及重要fetch结果ID以便接续。

## 报告最低内容

1. 本路回答了什么，哪些结论仍未闭合。
2. 来源表：作者/年份/题名/URL/材料类型/实际读取范围/适用文类或研究样本。
3. 核心结论及对应依据；给具体文本例或研究条件。
4. 对当前候选原则的支持、反例、需要收窄的地方。
5. 可操作的写作检查或开头做法，明确哪些是来源建议、哪些是本任务推导。
6. 对技能的少量候选修改，以及不建议加入的内容。

正文以约2000–3500汉字为目标，来源索引另列；重要信息不为凑篇幅而删。
