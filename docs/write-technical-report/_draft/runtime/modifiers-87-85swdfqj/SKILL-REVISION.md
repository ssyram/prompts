# `write-technical-report` 修订方案

## 状态与目标

本文件对应 [SKILL-DRAFT.md](SKILL-DRAFT.md)。该文件是完整、可独立使用的候选正文；**尚未替换** `本地代理资料（未随归档提供）`，也没有修改现有参考文件。

技能用于通用技术报告、方案和设计说明，按具体任务与读者组织内容。指定读者已表现的偏好被落实为默认写法：在多种忠实、充分的表达中，优先直接说明对象与用途、关系与条件，用核心办法和贯通案例组织正文，删去不承担说明任务的修辞。

具体判断依据、来源和限制见 [SYNTHESIS.md](SYNTHESIS.md)。

## 要替换的中心关系

旧技能的有效内容主要围绕材料真实性、修饰词、行为描述、固定正文顺序和交付前核对展开。它容易从“已经有一篇稿”开始处理句子，随后才考虑文章是否承担了正确任务。

候选技能改为以下主干：

```text
实际任务、事实和读者处境
→ 本文必须让读者理解或判断的事项
→ 所需对象、关系、条件、证据与案例
→ 选择有理由的组织和表达方案
→ 全文与逐句回查，并按发现回改
```

这不是把写作变成强制的线性流程。案例、图表或逐句检查可能发现缺口，作者应回到前面的任务、内容或组织层修正。它也不是把“没有唯一写法”误解为“只剩抽象原则”：候选稿给出有条件的默认开头骨架、正文组织和改句动作。

## 保留、替换与排除

| 当前能力或说法 | 候选中的处理 | 原因 |
|---|---|---|
| 读指定样文；不照搬术语、数字和结论 | **保留并前移到材料核对** | 样文是写法材料，不是当前项目事实或模板权威。 |
| 不降低目标、不把设计写成实测、不把猜测写成事实 | **保留并扩展为事实/目标/授权缺口处理** | 真实性和任务范围高于任何风格偏好。 |
| 用对象、动作、条件、结果替代空泛评价 | **保留并扩展为对象、关系、依据和作用范围** | 行为说明仍必要；术语已定义不代表关系已清楚。 |
| “可能”“只读”“同一次”等限定不能删 | **保留，加入证据强度、比较和句际关系** | 限定不只存在于执行条件，也存在于主张范围和确信程度。 |
| 同一对象同一名称；图、命令、表格与正文一致 | **保留** | 它们直接保护可追踪性和真实性。 |
| 开头“用途与验收要求 → 方案 → 案例” | **替换为按当前缺口选择入口** | 该顺序适合部分指定读者方案说明，不适合所有摘要、问题说明或证据型报告。 |
| 先逐句检查修饰词，再组织正文 | **以任务与必要内容指导逐句处理，允许往返修订** | 每句变清楚不证明该讲的内容已出现；也不要求作者按固定次序构稿。 |
| “材料不足时指出缺少什么” | **保留并区分两类缺口** | 缺事实、目标或授权时应查证/澄清；仅有多个写法候选时应由作者选择。 |
| 逐句问法、入口表与例子数量 | **分别保留实际作用，不作为完备定义或配额** | 局部硬要求仍有效，但局部检查通过不证明整体充分；入口和例子提供写法，不限定所有可行写法。 |
| “没有提供信息”条目下的修辞删除表述 | **保留删除纯修辞的意图，明确所指、作用和依据** | 避免被误读成所有评价与强调都禁用；原技能并未把有信息的限定一律列为禁项。 |
| 以篇幅或词频下降证明改进 | **明确排除** | 压缩可能把关系、条件或证据重建工作转移给读者。 |

## 候选正文的结构与作用

| 候选部分 | 它要求作者实际完成什么 | 与旧稿相比的关键变化 |
|---|---|---|
| 目的与使用方式 | 明确通用沟通任务、面向指定读者的写法默认及适用条件 | 不将指定读者偏好伪装成普遍实验结论，也不要求正常报告介绍写作方法。 |
| 取得本次任务 | 区分委托规定的说明任务、事实约束、读者与场景决定的解释深度 | 它们共同约束文稿，不硬排成可以相互抵消的优先序；不从标题目录反推任务。 |
| 构成必须说明的内容 | 让对象、关系、条件、证据、范围和案例共同完成任务 | 同时检查“已写内容有贡献”与“必需内容已覆盖”。 |
| 处理缺口和选择 | 区分应查证/澄清的事实缺口与作者应承担的表达选择 | 不因模板不匹配停工；也不把无依据主张改称“目标”来绕过缺口。 |
| 选择开头和正文组织 | 给出条件、骨架与改变条件，并用规则语言介绍、受限选型的成文开头示范取舍 | 默认不强制一种入口；对象已知且要作判断时，不为套模板重讲定义。 |
| 说明机制和案例 | 以“文件标签自动附着”为例，从已有机制补出应说明的关系；让图、配置和文字接通 | 区分任务需要的展开与无必要细节；案例不自动证明覆盖、性能或安全。 |
| 逐句表达 | 检查修饰语挂接、关系、依据、范围和改后保真；选择保留、移位、补关系、展开或删除 | 不用词类黑名单、长句阈值或“全部拆开”。 |
| 整体核对与交付 | 回到任务、范围、证据和读者责任，检查整篇而非局部清单 | 不把“每句可解释”或“字数变少”当合格证明。 |

技能主体不要求作者创建新脚本、画像、需求矩阵、审查门槛或读者实验。作者可以在内部列出“读者需要能判断什么”，但正常交付仍是技术报告本身和必要的变更说明。

## 面向指定读者的写法默认怎样落在候选中

候选不是只在开头说一次“面向指定读者”。它在三处持续发生：

1. **原则层**：任务、事实和范围优先；信息先足够，再减少无当前贡献的负担。
2. **推荐层**：当需求已共享而新对象未定位时，优先“对象类别与用途 → 使用者能做什么 → 核心办法 → 贯通案例”；当问题未共享或报告承担决策任务时，切换到相应骨架。
3. **表达层**：优先直接写谁对什么做什么、条件怎样改变结果、比较依据是什么；保留必要限定，不靠形容词堆叠给出结论。

因此，指定读者偏好既不压过任务，也不会只作为“某个指定读者恰好喜欢的示例”。若明确委托、读者知识或证据状态使另一写法更合适，候选要求说明并采用另一写法。

## 有意不加入的内容

候选不加入：

- 固定开头种数、固定摘要字数、固定 CARS/IMRaD/WHAT→WHY→HOW 章序；
- 每段一项义务、每句一套槽位、每篇一张任务矩阵；
- 形容词黑名单、名词串数量阈值、所有评价量化、所有长句拆短；
- 强制读者复述、A/B 测试、独立审查 gate 或额外研究；
- Grice、Miller、Occam 等理论名词和本轮讨论史；
- 将 Tool Auth Lang 的能力、样例或数据照搬到其他项目。

排除这些内容不表示它们永远无用；它们没有在本技能的每次调用中取得默认必需资格。

## 实施边界

若用户确认安装，替换目标为：

```text
本地代理资料（未随归档提供）
```

替换前应比较候选与当时实际安装版本，重新检查 frontmatter、相对链接和项目事实；不能假设今天的候选仍自动覆盖未来新增的实际约束。正式更新时一并核对 `references/style-examples.md`，必要处同步修正用途说明并保留史料边界。候选正文不依赖该文件，本轮两个安装位置均未修改。

本轮已交付三份不同职责的文件：

- [SYNTHESIS.md](SYNTHESIS.md)：为什么这样改、来源和边界；
- 本文件：改什么、不改什么、候选对应关系；
- [SKILL-DRAFT.md](SKILL-DRAFT.md)：可直接复制为 `SKILL.md` 的候选正文。
