# What is a Bug：概念形成的后见整理

本文是根据[发生记录](archaeology.md)与[讨论记录](../../../what-is-bug-discussion-log.md)作出的概念重构，不代替原始消息，也不声称过程必然通向现稿。

## 1. 主干：关系判断与三个构成方面

用户提出“意图、可达、后果”，后来将意图定名为规范意图，并强调三者共同形成有机判断。现稿先给完整关系定义，再说明三个方面；避免把三份独立材料的存在当成关系已成立。

依据：发生记录 §4–§6；用户讨论中对“意图范围”“后果判定”“三元组与有机判断”的纠正。

## 2. 论域与严格度

论域决定讨论允许纳入的规范意图、合法场景及后果判定。严格度限定论域取值，严格通常偏具体、形式、明确文本，宽泛容纳更多常识、概念与抽象原则。

逻辑要求保持。早期助手把“更安全”等绝对称为伪意图，又曾要求各方面同步收放；现稿均以可定制论域代替这些固定限制。

依据：发生记录 §4–§5。

## 3. 意图内容与意图根据

规范意图回答想做什么，授权来源及解释回答外部分析者凭什么把该意图归给对象。明言与非明言授权均可进入适当论域；推导需要前提和桥接关系。

这解释了本案中“其它地方已有测试”为什么只能先成为线索：还需要论证怎样从局部检查推到候选处的义务。

依据：发生记录 §5；讨论中用户关于“意图是内容，来源是佐证”的纠正。

## 4. 检查证明与发现候选

现稿以二阶论证检查为主责：分析现有论证的前提、推理和论域资格。发现过程可以综合、辩证；推荐用于排除不构成禁止发现的边界。

可达性检查针对当前论证必需的条件，而非重新展开一次全系统找反例任务。

依据：发生记录 §5–§6。

## 5. 实战方法与定义分层

文档规定 → 代码公开允许 → 常识排除兜底，是常见工程默认论域的识别方法。它不是关于所有对象的普遍定义。

“先运行”“用暂停点复现”“给文档做对照”都是推荐方法；论证的成立取决于它们实际支持了哪些前提。

依据：发生记录 §4、§6。

## 6. 发布文本中的选择

- 抽象定义保持正面、精确；否定性纠偏集中于 Q&A。
- 方法论按意图、可达、后果和二阶核查组织。
- 两种模板分别服务工程行为与非形式化规范冲突。
- 哲学说明和工程经验作为附录，不反向成为每次必须执行的额外流程。

这些选择对应用户最后的编排、压缩与措辞要求。评价其实际效果，需要看后续使用结果，而不能仅从文本已存在推出成功。
