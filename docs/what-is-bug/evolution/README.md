# What is a Bug：讨论沿革

本目录保存一次从 PR 审查争议转向 Bug 定义与论证检查的讨论。现役文本位于 [current/what-is-bug.md](../../../current/what-is-bug.md)。

## 材料与阅读顺序

1. [讨论记录](../what-is-bug-discussion-log.md)：按会话顺序保存用户要求、助手答复和后续纠正。历史答复包括后来被否定的说法，不具有现役规范效力。
2. [发生记录](archaeology.md)：交代原始动因、讨论分支、草稿变动及记录范围。
3. [概念形成](concept-formation.md)：从讨论中重构最后采用的结构，明确这是后见整理。
4. [经验反思](reflection.md)：从本案例提取有适用边界的经验。
5. [首次使用测试](usage-trial.md)：GLM-5.4 筛选旧 review 的结果，以及主代理回源核对后的修正。

## 证据与权限

- 讨论记录由本次会话的消息文本整理而成，省略工具回显、自动通知和消息附带的重复资源正文；个人标识与本机绝对路径作脱敏处理。
- 发生记录依照消息的实际先后及明确回复关系组织。较晚的反对作为较晚事件记录，不倒写成早期参与者已经具有的认识。
- 概念形成和经验反思是事后解释，其依据是本次讨论，不能冒充独立的工程验证。
- 此处记录的是 SKILL 的形成史，不是对原 PR 的新一轮审查，也不确认历史报告中的 Bug 结论。
- 当前规范由现役文件给出。历史中与现役文件冲突的草稿保留为历史材料。

本次整理没有读取用户另外保存的 `what-is-bug.md`、`what-is-bug-discussion-log.md` 两份重复材料；依据是本轮会话及用户最后确认的回答。
