# Reflection：这次真正学到什么

这里只留下能改变下一次判断的经验。完整证据账见 [`archaeology.md`](archaeology.md)，中段概括见 [`concept-formation.md`](concept-formation.md)，正式模型见 [`../architecture.md`](../architecture.md)。

## 1. 真正的抽象来自把一个案例逐层问到底

关键进展不是又收集一批原则，而是持续追问同一个 callgraph：问题需要什么能力，为什么采用这个方案，方案自身有什么限制，内部字段因此为什么存在。

只有这四层分开以后，才看见“问题不能直接推出字段”，也才有条件抽出后来更一般的 `F / X / X|F / x_i`。

## 2. 中间概念不能过早当作废话删除

“自在/他在”和 callgraph 案例没有进入最终 SKILL，但它们曾承载一个尚未说清的关系：当前整体、待引入方案、形成的新整体，以及下一层递归。

第一次自应用 Occam 把这些词和关系一起删弱，随后不得不补回分析性与递归性。判断标准应是：**删掉表达以后，它发现的关系是否仍被完整保留？**

## 3. 从案例上升到普遍结构，必须主动寻找案例偷偷带入的前提

“父结构”准确概括了字段所属的当前整体，却默认这个整体像一个解决方案。用户追问非设计对象和顶层对象以后，这个词才被拆成判断语境 `F` 与被分析对象 `X`。

普遍化不是把案例名称换成抽象名词，而是删除只在该案例成立的前提，同时保留真正参与判断的关系。

## 4. 当前框架比一句 Occam 多出的不是规则数量

它强制分开四件事：正在裁剪什么、什么有权规定判断、对象自身哪些事实相关、删除后必须完整保全什么。

如果一个新版只能说自己“更系统、更深入”，却说不出哪项取舍因此获得了新根据，它还没有证明自己比一句调用语更强。

## 5. 语境值得优先检查，但不值得无限考古

若两个仍合理的语境解释会导致不同的删除结论，先继续核对语境；若它们对当前裁剪结论相同，就停止。需要消除的是会改变决定的不确定性，不是所有未知。

## 6. 好概念应当能纠正自己的实现

`X|F` 的价值不只在解释 callgraph。它后来具体发现了：对象又被偷写成方案、对象性质参与循环自证、近期 pattern 被过量编译、核心符号被使用却没有定义。

一个抽象若不能指出哪句话该删、该补或该改，多半只是标签。

## 7. 历史配重按概念作用，不按材料数量

一次短回答可以完成关键统一，但不能据此占有此前积累；大量资料可以提供反例和边界，也可能没有改变核心设计。判断贡献只问：它具体改变了哪个关系，后来是否真的被承接。

起因、案例、过渡概念、闭合节点和事后解释必须分别记录；否则最顺的故事通常不是实际发生的历史。
