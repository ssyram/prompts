# Context Recalibration Cases

## Purpose and evidence status

This file is a replay corpus for `architecture.md` P.1/M.1. It records observed cases in which the context around an object was either recovered or replaced by procedure-generated material. The cases help test the general rule; they do not define a closed taxonomy.

The borrowed operational reference is `/recalibration` at content SHA-256 `cd8604c4eee833a0845398d6655522097106bc1d83290a03f6f03c0da2ddc7ab`. Its observed usefulness is partial rather than a correctness guarantee.

## Successful restorations

### Chamberlain origin

- **X:** the organizing account for the chamberlain design.
- **Polluted frame:** infer an elegant origin from the finished artifact or from recently discussed architectonic concepts.
- **Recovered chain:** the main AI thread is occupied while side work still exists → the user needs rapid switching and high-level control → a steward-like AI keeps oversight and supervises delegated work.
- **Expected result:** the historical need governs the account; retrospective philosophical organization may explain it but cannot replace its origin.

### Occam root goal

- **X:** the Occam skill and its design.
- **Polluted frame:** treat garbage collection, concept clusters, viewpoint analysis, or one recent technical example as the root purpose.
- **Recovered chain:** preserve the user's actual need while removing everything without necessary contribution → establish the context that determines necessity → recursively test the contents of the given object. Garbage collection is one possible effect.
- **Expected result:** derived mechanisms remain subordinate; the skill is not narrowed to the most recently successful explanation.

### Local design component

- **X:** a confirmed local component in a larger design.
- **Polluted frame:** remove it because it arose during discussion, or retain every neighboring candidate because they arose together.
- **Recovered chain:** final system goal → still-active parent design responsibility → component's assigned local obligation.
- **Expected result:** the component remains only when this live chain and its current evidence survive; rejected sibling candidates and their private consequences leave.

## Observed failure families

### A passing term becomes a requirement

A suggestion such as “interview” was introduced while discussing how to recover source material, then restated as if the final method inherently required interviews. The user had not supplied that goal. The term belonged to the procedure context and should have left unless a real source gap independently required it.

### A derived effect becomes the root

Garbage collection was a useful description of one Occam effect, but repeated discussion made it appear to be the whole skill. The valid direction runs from minimum-sufficient preservation to the removal of unsupported clusters, not from the metaphor back to the user's complete purpose.

### A finished artifact fabricates its own history

An account was reconstructed from what the current design looked like rather than from why the user needed it. This produced a coherent but false motivation. Existing artifact properties belong to `A(X)`, as defined in `architecture.md`; they cannot manufacture the goal chain that authorizes them.

### A local difficulty replaces its parent goal

Review completion, a file shape, a state representation, or a temporary optimization axis became the apparent completion condition. Each was at most a local task. Without a still-valid path to its parent responsibility and the user's final goal, it had no authority over `X`.

### Wrong or abandoned frames remain live

Rejected candidates, disproved interpretations, failed search paths, and their private descendants continued to organize later output. Their process history should leave; only a verified result still required by the live goal chain or a confirmed rejection boundary may remain.

### AI inventions become facts by repetition

Invented reviewers, states, guards, fallback paths, fields, or classifications were expanded until their internal consistency looked like evidence. Repetition and downstream detail do not supply a user decision, object fact, or parent obligation.

### Process deliverables leak into the object

A worker added an acceptance report that the task had explicitly omitted. The report served orchestration rather than the actual deliverable, so process usefulness did not establish necessity inside `X`.

### A definition is removed while its use remains

The runtime skill retained `A(X)` in its procedure and example after its definition had been omitted from the internal model. The local text became shorter, but the surviving symbol could no longer be interpreted from the skill itself. A definition, source, premise, or referenced target cannot be removed while dependent content remains.

### Partial sound cases replace the principle

Several valid retain/delete patterns were listed and thereby made to look exhaustive. Unlisted structures then escaped judgment. Examples may discover candidates, but every candidate must return to the same `X|F` deletion test.

## Replay expectation

For each case, a successful run must keep the user-given `X` stable, recover a sourced path from final goal through every still-valid intermediate goal to `X`, reconstruct current facts without upgrading plans or claims, and remove procedure history that has no remaining authority. A failure in any one of these dimensions invalidates the resulting `F` even if the final wording is concise.
