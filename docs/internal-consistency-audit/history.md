# 内部一致性审查：实战演进与方法定型

## 1. 缘起：从单点修补到按使用点全量扇出

本方法在一套多角色状态机与门禁体系的两轮连续实战审查中定型。

起初是逐份校准各阶段提示词与手册。单点校对中连续暴露出一类共同问题：每份文档单独读都通顺，但执行者真正照着文档去读任务包、调命令、写文件、过门禁时，上下游在接缝处撞车——例如提示词教的字段名与任务包实际生成的字段名不同、异常上报写完后被自身提交门禁拦截、两本手册对同一集合用了不同称呼。

由此确立第一条方法主线：**围绕具体使用点做全量并发审查**，把“收集层（多路独立取证）”与“判断层（主代理亲核代码、去重排假、分流决策项）”拆开。

## 2. 第一轮实战：消费者首次接手镜头（菜单甲）

第一轮针对多角色分析状态机及其配套手册，按“谁读到什么”派出 7 路并发收集：各阶段执行 worker 镜头、主调度循环镜头、跨文档引用与结构镜头、全局术语镜头、设计文档↔现行提示词对照镜头、历史残留镜头。

- **捕获的典型问题形态**：
  - 同一阶段在状态机指令与执行手册中的任务边界不一致（例如把专项结构任务混入常规等价类批次）；
  - 提示词要求执行者上报某类发现，但下游接收门禁只放行固定子集，导致合规上报即被拦死；
  - 流程中首次出现的运算符号与共享底稿缺失处理规则，在消费者可见范围内无定义；
  - 提示词引用的章节虽然存在，但跳过去之后只有原则概述、没有当前步骤必需的命令格式。
- **判断层证伪的作用**：收集层交回的高危候选中，有 3 条经主代理核对门禁源码与状态机完整配置后确认属于误报（如权限白名单在对应状态实际已放行、只读查询在指定参数下已闭合）。这确立了**“子代理候选必须经主代理查源头核实后才进终稿”**的铁律。

## 3. 第二轮实战：八轴跨组件关系审查（菜单乙）

第二轮针对接入完整验证流水线的新四态分析段及其上下游门禁，升级为按**跨组件关系轴（W1–W8）**并发扇出，将状态转移×门禁副作用（W3）、多机制共享状态交互（W6）、测试反假绿（W8）列为强推理主轴。

- **捕获的机制级死结与假绿形态**：
  - **硬门毁材料＋软拒锁死状态（W3）**：分流态选择“宣告失败”时，出边硬门先把用户据以决策的原始中止报告覆盖成新骨架，导致紧随其后的软审读不到原报告；一旦软审拒绝留态，硬门刚写下的文件又触发该状态的写保护检查，把全部三条重试出路永久拦死——而该状态的工具白名单里没有任何清理手段。
  - **前态合规产物被后态当成违规脏文件（W3/W5）**：前一步按要求生成的辅助文件，在下一步的产物白名单检查中被判为非法额外文件，同时来源态的写保护又禁止删除。
  - **邻居闭包要求与固定节点禁改令正面相撞（W6）**：返工门禁强制要求报告覆盖全部图邻居，而其中的固定契约节点受另一条“严禁挂请求或重交”的规则保护，两头堵死。
  - **相邻提交冲掉真实输入版本（W5/W6）**：失效检查用相邻 git commit 代替已接受输入代次，导致正常的多步提交改变了失效判定。
  - **跨宿主环境崩溃（W2/W6）**：死批报告默认强依赖单一宿主的守护进程地址，在无该地址的宿主环境下直接抛错崩溃。
  - **测试假绿链（W8）**：测试 runner 在子项失败后仍返回退出码 0；续跑逻辑把上一轮旧绿当成本轮通过；端到端套件全量 skip 仍记为通过；专项测试把恰好处在被测路径上的校验函数 mock 掉。

## 4. 实战沉淀的六条关键修正

1. **自由探索优于预设排除清单**：曾尝试向后续 worker 下发“已知问题清单”要求只找增量，被负责人及时叫停——多路互盲独立撞上同一问题恰好提供交叉核查，去重由主代理统一完成。
2. **真分叉才进决策项**：曾把“出态落盘的具体技术手段”“半途注册失败的底层补偿写法”列为决策项请负责人拍板，被负责人退回——目标与对外契约已定时的技术选型归实现者直接拍板（进非决策项）；只有不同选法会改变对外契约、角色权责或允许行为边界的真分叉才进决策项。
3. **报告必须说人话、前因后果自足**：初版清单写成“`A_PREPARE` 写‘沿用’ vs 门禁拦截”这类面向 AI 上下文的速记，负责人阅读时缺少上下文。随后确立铁律：每条决策项必须先用自然语言交代“这是哪一步、角色当时在干什么、原本为什么这么设计、两边撞在一起一步步怎么卡死”，让人无需打开源码即可拍板。
4. **先查配额再扇出**：曾因未查模型池余量直接并发派发，导致整批子任务起步即因额度耗尽失败；此后固定将 `provider_usage` 检查作为扇出前置动作。
5. **自然语言模型配强制引用纪律**：自然语言擅长的模型在长文扫描时召回广，但容易把措辞差异升格为机制冲突；通过强制要求“贴两端原文＋写出两种读法各自导出的具体动作差异”显著压低了假阳性。
6. **超时先从 transcript 末尾 `write` 调用打捞**：两轮实战中均有 worker 在生成完完整报告、最后一步写盘或收尾时触发会话超时，直接从其 transcript 的 `write` 参数中完整救回报告正文。
