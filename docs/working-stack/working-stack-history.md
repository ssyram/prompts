# 用 working-stack 开发 working-stack：去敏工作栈

> **重要研发历史实物，而非另一份现行规范。**原方法线曾结束、活动栈为空；后来用户因实际使用的新发现另开持续迭代根帧，旧节点的完成不被撤销。帧树、已完成计划、局部原则及其去向仍在。实际业务主题、个人路径、原始对话定位和提交号已泛化；`B-xx` 是此实例的稳定帧 ID，`T` 指另一条任务讨论线。方法的现行用法见 [`current/working-stack.md`](../../current/working-stack.md)，形成理由见本目录 [README](README.md)。

这份记录展示的是**方法怎样被讨论、纠正、落实、发布和关闭**，不把后来的清晰结构倒写成初期就按该结构执行过。[B-02]、[B-03] 是事后补建的逻辑父节点；[B-01] 原有的 ID、已 pop 身份和早期提交史没有因此变成一次从 [B-03] 发起的真实 push。

## 全局原则

- **B/G1｜帧树。**每帧有稳定 ID 和上帧；活动路径是栈。已 pop 节点保留、可按 ID 回查，**不可重新进入活动路径**；新独立目标另开帧并在来源中引用旧 ID。旧帧可补历史说明，不追改原目标或当时的达成事实。
- **B/G2｜帧内容。**每帧记录来源、弹帧目标、计划与 FOCUS、已得结果、外部执行事项、确立原则和可多条的备注。已 pop 帧在目标下方紧接“达成情况”（结果／对应／依据）。
- **B/G3｜push。**开始非微小计划项时默认 push 有自身 FOCUS、目标的子帧；微小推进留本帧，不为每次工具调用造帧。子帧完成不自动把父计划项标 done。
- **B/G4｜pop。**目标达成则记完成；原目标不再重要且用户确认停止，才可记 `[expired]`，不记 done。以“判断真假”为目标时可靠反例可以完成目标；以“证明为真”为目标则不能借反例假装完成，只有目标失去价值才可 expired。目标仍重要且未达，不假 pop；计划耗尽可短暂 push planning 帧确定下一步。
- **B/G5｜返回路标。**每次 pop 在回复中说明返回哪个 ID、该帧 FOCUS 和下一项；不在已 pop 帧另存一份回程导航。立即再 push 也先说清返回任务。
- **B/G6｜原则历史。**原有原则不删：逐条标 `released → <接收原则 ID>`、`kept-local`，或在被推翻时标 `invalidated` 并说明理由。过期帧的原则不自动上移。原本误列为原则的事实保留旧 ID、移至结果或备注并标 `reclassified`；若已 release，要同时修订接收处。父计划须自己写明责任，不能只借子帧 ID 代述。
- **B/G7｜岔题。**普通旁支用用户确认的 `[digression]`；有独立目标才 push，不把它误称为规格 `deviation`。
- **B/G8｜落盘节奏。**本实例把任务讨论线与方法讨论线分存两个文件，用无 remote 的独立本地 Git 保存历史；短答可先留会话，工具／调研任务时合并更新、提交并向用户简报。这是**本实例的安排**，不是跨主题强制目录方案。
- **B/G9｜证据读取。**用工具前明确要找的事实和源锚；优先使用已有的阅读摘要，不为一般理解反复整读；要求逐字时才取精确原文。
- **B/G10｜pop 的子树汇总。**pop 时回顾本帧下整棵执行子树，以原弹帧目标综合判断实际达成；只把与上层有关的关键结果、原则和外部副作用概括给父帧或留节点指针。过期内容只留历史，不向祖先重复抄录。
- **B/G11｜来源。**每帧说明来源；根帧及 `[digression]` 尤其说明为何存在，普通子帧简述使其成立的事实。
- **B/G12｜活动帧责任。**活动帧只记本帧及上层当前已知的工作，不预写下层将来的执行或汇总；pop 后才可概括下层。
- **B/G13｜书写顺序。**活动帧先于所有已 pop 帧；树关系由上帧 ID 表示，不靠正文交错摆放。
- **B/G14｜内容性质。**可有多个 `备注 · <名称>`，记录事实、背景、用户新增认知或待核判断及其证据身份；`确立原则`只记录用户明确确认、后续须遵守的局部规则或临时设计决定。重要事实不会自动变成原则。
- **B/G15｜两处状态。**`## 栈状态` 从根到顶只写 ID 与短名称，唯末行标 `[TOP]`／`[PAUSED]`；岔题顶可标 `[TOP/digression]`。各帧标题另标 `[ACTIVE]`／`[TOP]`／`[PAUSED]`／`[POPPED]`，上帧字段使用中文。
- **B/G16｜结果可见性。**字段名用“已得结果”；不同的结果各占一项，不揉成一段难以辨认的文字。
- **B/G17｜外部执行事项。**只记实际可观察的副作用；只读调研有收获但没有修改，就不能充当副作用。
- **B/G18｜记载门槛与归属。**先判断内容是否非平凡，再沿根到当前帧找到最贴合目标的归属；重要不等于在每个祖先重复记录。
- **B/G19｜目标回应。**与弹帧目标有关的非平凡收获进“已得结果”；以学习为目标时，有据且获用户认可的新理解也可算结果。标签可以是 `[认知习得]`、`[认知细化]` 或 `[实验结果]`，不是固定枚举。
- **B/G20｜简短而可见。**压缩表达不可省去 FOCUS、完成项和原则的必要可见性。
- **B/G21｜目标—达成关系。**pop 时先概括整棵执行子树与原目标的总体关系，再在已有“对应／依据”中逐点说明：正向是原目标自身实现了什么、实现多少；反向是原目标本体或认知前提怎样被推翻；正交是原目标之外、但有来源依据证明符合原意并丰富原目标的成果。只写实际出现的方向；来源关系未明时不冒称正交。不增加字段，逐父帧核子结果能否支撑父目标，不追改旧目标或以子帧成功冒充父项完成。
- **B/G22｜现有结构检查器。**工作线已附结构检查脚本时，在栈文件修改后、提交前运行；只核活动路径、父链、pop 达成栏位和不复活的结构，不代替用户的语义验收。其他工作线没附脚本不因此受阻，纯回答不单为检查调用工具。

## [B-11] [PAUSED] 持续迭代 Working Stack

- 上帧：无（新一轮独立根帧，不重新打开已完成的 [B-02]）。
- 来源：用户在使用工作栈时发现目标与结果并非总能直接对应，要求持续记录后续方法修订并更新公开去敏历史。
- 弹帧目标：用户确认持续维护已不再需要，且已接受的规则已进入本地方法、公开提示词与去敏记录；一次发布本身不完成长期任务。
- 计划：
  - [done] 用 [B-12] 澄清本次差异并形成规则。
  - [done] 第一轮把差异规则写入方法、公开提示词和本实例。
  - [done] 通过 [B-15] 将重复结构检查归入本地方法旁的单一脚本，并在方法中说明条件性使用。
  - **[FOCUS/in_progress]** 在另一条任务线的后续真实使用中留意具体目标—达成偏差；只有出现用户确认的新反馈时才修订。目前本方法线暂停，另一任务线继续。
  - [ready] 用户决定不再继续迭代时，核目标后才讨论 pop。
- 已得结果：[方法决定] 只强化现有“达成情况”的语义要求，不增加字段、状态或审查流程。
- 外部执行事项：本地方法文本、公开提示词和去敏实例已在本轮更新并发布；具体提交与推送以仓库记录为准。
- 确立原则：无；[B-12] 的局部原则已释放到 B/G21，不在父帧重复。
- 备注 · 状态：另一条任务讨论线仍在进行，本方法迭代线暂停，不等于完成。
